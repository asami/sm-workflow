## Ordinary host configuration

`sm-workflow.repository-sync.program-inputs` is an optional normal component parameter. It contains:

- `coverage`: each fixed existing `check` (`identity`, ordinal, kind), its `affectedPaths`, complete `inputPaths` consumption scopes, and rationale.
- `fullChecks`: existing fixed checks for integrated FULL, with no new HEAVY selection.
- `fullPaths`: explicit broad build/dependency/generator/runtime input scopes and `reason` explaining their impact.
- `priorEvidence`: optional native locators `{session, validation, closure}`. Validation uses the actual `session:ordered-validation:<frontier>:validation` reference; closure uses the actual committed `session:ordered-step-closure:<frontier>:committed` reference. These fields contain no success flag, receipt, accepted result or authority.

This parameter is used together with S2's document/consumed declaration and existing typed process/workspace grants. Host mappings must describe the actual product consumption and fixed check coverage. Every coverage entry must include its affected scope and every declared broad input scope among its consumed inputs. The fixture uses real Java source plus runtime value input; Scala changes still require selected actual FixCheck evidence under the existing merge guard.

Actual changed consumed/unknown paths determine selection. Bounded paths select the union of relevant coverage. Explicit broad paths or uncovered changed inputs select FULL and record the actual path names and impact rationale. Neither merge, UPDATED, commit IDs nor metadata is an input to that selection. The ordinary product's FULL test contract remains distinct from separately selected HEAVY; this implementation does not redefine suite membership or execute a heavy batch.

Missing program policy leaves the S2 precise unresolved-program outcome. Missing native references, mismatched repository/principal/history/candidate, failed validation or uncommitted closure cannot supply reusable success. A valid original result with changed consumed inputs supplies no reuse and the selected check executes normally. ## Meaningful applicability and review limits

A reference is only a locator. Runtime loads the actual GoalPhase Start, successful native validation and committed accepted Step closure through the existing managed storage owner. It checks actual instance-history prefixes, original repository root/branch and principal, selected Step/candidate and observed closure tree. It then reads typed changes from the original validated tree to the pending merged tree. A check is reused only if its fixed identity/ordinal/kind match and no path/mode/blob delta touches that check's complete consumed scopes. Commit messages, documentation and explanatory rationale may change without invalidating those inputs.

The retained receipt is the original actual receipt, including its raw process observation where present. It is never replaced with a new fabricated PASS. Its validation and closure references are saved in the normal validation state. Original accepted review evidence remains explicitly original review context; reviewless Step admission supplies no review reference. Reusing validation does not establish review acceptance. New parent overlap, conflict resolution, contract paths, repair findings or unexamined binary/unknown inputs still use existing conditional semantic assessment and paired continuation. Large diff/range access remains the S2 implementation.
