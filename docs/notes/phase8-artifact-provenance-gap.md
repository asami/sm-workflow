## Current required contract and authored connection

The operational trust boundary is actual normal publication records and ordinary
dependency resolution. An unchanged SNAPSHOT version alone is insufficient:
the exact selected normal publication result/request, producer owner/process,
artifact and recollection provenance, selected dependency source/consumption,
consumer requirements, purpose, ownership, exclusions and effect authority must
remain covered by the original actual adoption. A changed current consumer
candidate tree/frontier/generation alone does not create a new Human decision.

`GoalPhaseDependencyPublicationSourceAlignment` retains the original independently
admitted Direction. The normal Goal continuation can append a mechanical
applicability receipt that references the exact prior native receipt and binds
the current candidate under that unchanged contract. Historical reconstruction
requires the unique earlier native adoption and its actual adjacent history;
a caller-authored answer cannot supply it. Current source/roots/policies are
rechecked and existing `LocalPublication.collectC` / `collectLatestC` must still
select the exact adopted successful normal publication. A newer successful
replacement, latest failed/UNKNOWN writer, missing record, stale source, changed
dependency owner/selection/Usage or effect policy cannot inherit the adoption.
Current consumer verification selectors/program mappings are independently validated
by the existing source/check owners; they are not the artifact's Usage/acceptance
meaning. The typed comparison preserves actual approval and acceptance coverage,
source/root/workspace/exclusions and full admitted execution plan/grants while
allowing new affected tests. No whole test/coverage JSON or consumer tree is used
as a second artifact approval boundary. The ordinary
review/closing freshness path rechecks current applicability as well.

This operation executes no publication, grants no primary publication attempt,
resets no repair count and inherits no successful check/review for the changed
consumer. Required current affected validation and independent review remain.
The existing pure/local alignment specifications cover prospective candidate-only
reuse, contract changes, closed receipt references and real in-memory normal
publication algorithm ordering, including superseding success/failure/UNKNOWN,
missing result and changed owner. All are authored, unexecuted specifications.

There is no claim to detect manual unrecorded replacement of JAR/archive bytes,
no digest pin, new CNCF observation API or parallel verifier/approval ledger.
Those would be a separate requirement with its own owner/effects. They are not
silently weakened or falsely certified here; they were never part of this Goal.
