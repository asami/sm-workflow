## Normal configuration contract

The component parameter `sm-workflow.repository-sync.dirty-purposes` is a JSON
object with `sources` and `slots`. Sources are bounded objects containing `kind`
(Task, Step, Finding or Journal), `identity` and `revision`. These must be real
retained records from the current host, not fabricated receipts. Step sources use
the actual GoalPhase native Start reference and Task sources the actual GoalTask
native state reference. Journal/Finding references use actual Journal entry
identity/revision; Finding must identify a real finding entry. The request
contains their actual payload/status. Existing records inform grouping; their
presence never accepts a new content candidate.

Each slot has `workspace`, `checks`, `actionPolicy`, and optional `checkWorkspaces`.
Slots are ordered execution resources: every materialized purpose candidate or FIX
retry consumes the next fixed empty workspace. Supply enough distinct slots for
the admitted plan and bounded retries. The existing host process-execution plan
must register each slot's distinct empty directory and Manage workspace grant.
Materialization refuses a nonempty, overlapping or source-root destination.
CNCF creates a detached worktree at the exact prepared commit; no arbitrary
caller path is accepted.

`checks` are existing `{identity, ordinal, kind}` native checks. `actionPolicy` is
the existing Step assessment policy with kind documentation/code, selected
conditional/required detailed review, lint settings and actual observations.
Unbound future Step deferrals are refused. Document slots can select an empty
product-check vector, while retaining actual structural Git checking. Code slots
retain the existing meaningful compile/behavioral/lint evidence gate and the S3
program-input coverage/FULL rationale policy.

Configure normal Git bindings/grants for slot Head, IndexTree, Status,
CheckPendingIndex and PendingDiff operations. Product SBT declarations must target
the exact candidate slot root. If several selected checks require distinct
TestOnly bindings, `checkWorkspaces` maps check identities to fixed workspace
aliases rooted at that same actual candidate directory; the runtime verifies
actual Git roots before executing them. They need their normal Git Root and SBT
operation bindings/grants. This is separate from the parent host's own CNCF/SM
implementation-validation binding; those checks qualify these source edits, not
product candidates in a user's dirty repository.

The ordinary source Git declaration must have the existing checkpoint-family
commit identity/authority and finite content/stdin/stdout/work-area limits large
enough for the selected text. New purpose operations remain typed Manage Git
operations. Inventory uses dynamic bounded TreeEntries backed by the existing
Tree read family. The runtime retains the public Start's real principal and
intent; no caller-created effect-import rows or approval facts are required.

Missing policy/slot, unsupported binary/mode/rename content, unknown source,
stale HEAD/index/worktree, conflicting remainder, failed materialization and
failed/unknown execution remain precise unresolved outcomes. Explicit exclusions
and their staging/content survive. After all admitted purposes, any dirty
remainder yields Wait; no stash/reset/checkpoint manufactures a clean state.
A later independently changed shared-file candidate, including a later group
whose captured content was invalidated by an earlier FIX, is refused as stale;
that semantic plan must be reconsidered rather than overwriting the repair.
