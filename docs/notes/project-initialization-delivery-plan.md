## Main route first

### INIT-1 — Reach initialization without project configuration

Define the concrete typed Operation and fixed installed CLI entry. Bootstrap a
minimal initialization assembly before the configured Workflow assembly. Prove
invocation in an existing repository with no sm-workflow config/runtime-root/DB.
Separate a genuinely missing installed runtime from a missing project installation.

### INIT-2 — Generate one usable GoalPhase installation

Use shared production defaults/contracts to create directories, DB and coherent
GoalPhase bindings. Reuse normal preparation for adopted Plan/test choices and
typed execution declarations. Eliminate the observed review-limit, forbidden Git
environment and missing-output-directory failures without relaxing valid contracts.
Prove initialization -> ordinary prepareGoalStart -> distinct authorized Start
and first Advance in an isolated representative project. Initialization itself
must perform no Start, Git/SBT validation or commit. Do not build a universal
configuration UI or all Workflow variants before this route works.

### INIT-3 — Reuse and incomplete-installation handling

Demonstrate repeat-safe reuse with existing overrides and Session/history/tests
unchanged. Handle actual partial preparation and conflicting/ambiguous configuration
with truthful per-resource results; never replace a live DB or invent migration.
Use existing storage/create-conflict behavior rather than new global locks or scans.

### INIT-4 — Skill delivery and consumer adoption

Connect sm-goal-phase to installation selection/initialization before ordinary
Start preparation. Keep human semantic decisions distinct from mechanical settings.
Deliver caller/runtime contracts together and an English adoption guide. The
control-center Session already observed as started must be preserved and reused;
no fresh Start solely to demonstrate the new feature. Other Workflow skills can
adopt the same Operation after the main path is delivered.
