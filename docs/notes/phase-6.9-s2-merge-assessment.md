The normal optional host parameter
`sm-workflow.repository-sync.document-inputs` describes the repository's actual
input consumption. It is configuration, not caller-built grant JSON or a new
approval ledger. Example for a build whose documentation is not consumed:

```json
{
  "documentPaths": ["docs", "README.md"],
  "consumedPaths": ["src", "build.sbt", "project", "scripts", "docs/generated-input"],
  "reason": "Declared build/runtime inputs include generated-input; remaining listed documents are not consumed"
}
```

Consumed scopes take precedence over document scopes. Unknown changed paths,
nonordinary file modes, unavailable blob content or an absent mapping do not
become document-only evidence. S2 returns the precise unresolved program/input
validation boundary before dispatching product checks. The configured declaration
must reflect actual consumption; putting a file under docs is insufficient.
The controlled specification build explicitly consumes its Scala/build files.
S1 Equal/local-ahead/fast-forward behavior does not require this declaration.
Legacy native Starts retain their earlier policy/effect contract.

Document-only validation selects the two real structural Git checks against the
parents, with no product SBT check. The current request's effect scope includes
CommitPending only after the existing convergence owner verifies actual native
merge admission or paired semantic acceptance. Configured CNCF Git grants still
admit the operation. No caller effect row, new executor or self-approved review
is introduced. Retained intents retain their existing no-blind-retry semantics.

## Retained text and public range access

`RepositorySyncNativeMergeReview.Policy.maximumDiffBytes` now bounds the inline
preview, not eligibility for semantic work. Large complete text is retained by
CommonEvidence when configured; without Evidence storage, the actual captured
text remains inline. All actual changed paths remain assigned. There is no
path-count or diff-size-only Human refusal. CNCF's real resource/capture limits
remain in effect: incomplete output is labeled unexamined and cannot be treated
as full coverage. Binary diffs expose their actual textual metadata and an
explicit appropriate-evidence gap instead of an invented text review.

A preview provides the public Evidence identity and parent. Existing
`EvidenceService.readEvidence` returns the retained full text. New
`EvidenceService.readEvidenceRange` takes:

```json
{
  "identity": "<actual identity returned in the preview>",
  "revision": "1",
  "startCharacter": 0,
  "characterCount": 16384
}
```

Offsets count Unicode code points from zero, preserving supplementary characters.
The count is1..65536. Results retain original source/storage metadata and identify
the returned range and total length in the message. Missing, disabled, invalid
and indeterminate Evidence keep their actual statuses. Neither reader executes
Git, SBT, AI, archive replay, Workflow Submit or Advance. CML, explicit ABI exports
and the published operation set include the new reader. Normal runtime generation
is required; no generated source was edited or generator executed by this agent.
