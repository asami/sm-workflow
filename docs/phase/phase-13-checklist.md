# Phase 13 Checklist

Status: PLANNED — 全項目OPEN。文書化は実装・接続検証の完了を意味しない。

## U13-01 接続確定

- [ ] CallerIntegration / Runtime / RuntimeRootを区別し、接続部分の型・設定・CLIに非ネットワークhostや旧名互換性を追加しない。既存Session/履歴は限定した採用変換で保持する。

- [ ] Codex固有情報は既存の呼出元へ要求を返す境界を確定する。既存観測を再利用し、ProcessExec取得proxyや別AI実行を追加しない。

- [ ] 対象host/adapterと実測API、親子包含、累積値、失敗時通知、最終回答後の表示位置を実際の契約に対応付ける。
- [ ] 呼び出し/Session/Run/Action/Stepとprovider実行/thread/turn/attemptの既存識別の対応、観測位置と再開範囲を確定する。
- [ ] モデル呼び出し数、実モデル、reasoning effortの取得可否と単位を確定し、要求設定やturn数との違いを記録する。
- [ ] 実際の推論先によるCodex/ローカルLLM/その他/未確認の区分を確定し、呼び出し元クライアントと分離する。
- [ ] CNCF Resourcesの再利用と必要な共通型拡張、Journal/Evidence接続、sm-*スキルの薄い投影を確定する。

## U13-02 GoalPhase主経路

- [ ] 呼出元の実観測を同じSession/呼び出しへ関連付けて継続する。情報取得待ちを新規Startや業務処理の再実行で代替しない。

- [ ] 実際のsm-goal-phase呼び出しと委譲先のusageを取得し、親＋子の非重複合計を保存・完了表示する。
- [ ] 親チャット自身の思考を含むモデル別回数と親/委譲先内訳を表示する。取得できない指標は実接続で限界を記録し、未取得/turn数の別表示を確認する。
- [ ] 同じ結果を新しい読取から取得でき、AI再実行・記録用AI・rawログのGit追加が不要である。
- [ ] 最終回答生成後のhost表示を実証する。回答前の表示しかできない経路は範囲を限定し、対応済みhostと区別する。

## U13-03 共通化・集計の境界

- [ ] RepositorySync/SplitPhaseで同じ計測・保存・終了表示を利用し、スキル別の集計器を作らない。
- [ ] Codexと利用可能なローカルLLMの実測を同じ記録経路に接続し、区分別token・回数・親/子・モデルとcoverageを表示する。未検証の接続を明示する。
- [ ] Codex経由のローカル推論、実行先切替、混在する親包括集計、未確認の実行先で二重計上・誤帰属しない。未使用と未取得を区別する。
- [ ] 親/子/孫、失敗と実再試行を含め、無関係な並行チャットを除外する。
- [ ] 子孫込みの親値、自己分だけの値、同一通知の再送/再読、累積更新で二重計上しない。
- [ ] 一つのturn内の複数モデル呼び出し、同一呼び出しの複数通知、実際の再試行を区別する。同じモデルを使う親/子、孫、モデル変更・不明モデルも正しく分類する。
- [ ] token・思考回数・モデル/役割内訳を別々にcoverage表示し、turn数やusage通知数から思考回数を捏造しない。effort未確認を実適用済みとしない。
- [ ] 再開時の開始位置、カウンタ変化、同一turnの複数呼び出し、範囲不明を正直に扱う。
- [ ] キャッシュ入力/推論出力は確認した包含関係に従う内訳とし、合計へ再加算しない。
- [ ] 一部未取得、全未取得、子孫数不明、継続中、キャンセル/失敗時の消費を区別し、未取得をゼロ扱いしない。
- [ ] 遅延通知で同じ呼び出しの集計を更新し、業務結果や修正回数を再実行/再計上しない。
- [ ] usage取得・保存・表示の失敗でも業務成功/制御返却を保持し、追加承認・AI待機loop・検証再実行を要求しない。

## U13-04 配備・検証・引渡し

- [ ] 対象host/スキルの実際の配備経路を確認し、三スキルの終了サマリーと未対応hostの未取得表示を検証する。
- [ ] 集計境界のfocused検証と必要な統合検証・レビューを記録し、fixtureと実測接続の証拠を区別する。
- [ ] 既存Goal/Session/Plan・受入れ・履歴・修正回数・検証結果を保持した採用手順と実際の利用可能範囲を引き渡す。
