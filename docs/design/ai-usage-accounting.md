# AI使用量の記録経路

Status: accepted design; Phase 13 implementation pending.
Date: 2026-10-22

[仕様](../spec/ai-usage-accounting.md)を正本とし、責務を次のように分ける。

2026-10-23採用：Codex固有情報は既存のCodex呼出元が取得する。必要時は
sm-workflowが情報要求を返し、呼出元から実観測を受け取って同じSessionを続ける。
既存通知・実行結果が足りれば再取得しない。CNCFに汎用host読取DSLを作らず、
別Codex実行を起動してcontextを再構築する経路も作らない。既存接続での読取API
利用と別モデル実行は区別する。取得不可は未取得のまま扱う。
[採用計画](../notes/codex-caller-information-adoption-plan.md)と
[terminal情報の仕様](../spec/host-terminal-source.md)を参照。

| 所有者 | 責務 |
| --- | --- |
| CallerIntegration / 実行adapter | 実際の実行・親子関係・usage通知を観測し、providerの範囲/累積の意味を正規化 |
| CNCF共通実行モデル | 既存Resourcesと実行識別を再利用し、必要な共通観測型だけ拡張 |
| sm-workflow | 呼び出しとの対応、非重複集計、計測状態、終了時投影、既存Journal/Evidenceへの接続 |
| sm-*スキル | 発行された意味処理と結果返却。CallerIntegrationのサマリーを利用し、自己計測や別の監視loopを持たない |

2026-10-23用語改訂：[正本](../spec/runtime-caller-terminology.md)に従い、既存本文の
hostのうち観測/表示主体はCallerIntegration、実行基盤はRuntimeとする。hostは
ネットワーク接続先に限定する。実装名の変更は採用計画で接続先と同時に行い、
既存実行識別や保存済み実測値は維持する。

```text
呼び出し開始・対象実行の関連付け
  → 親/子/孫の実際のusage通知
  → 共通の実行観測へ正規化・保存
  → 非重複範囲の集計＋未取得範囲
  → 通常終了/制御返却のサマリー
  → 遅延通知は同じ集計を更新
```

実行別観測と表示用集計を分ける。実行を識別する既存IDと観測位置で同じ通知を再加算せず、
累積値は同じ範囲の最新観測として扱う。子孫込みの観測と各子の観測のどちらを採用するかは
adapterの確認済み契約に従う。単なるthread累計には呼び出し開始前の履歴が含まれ得るため、
そのまま今回の消費量にはしない。既存の再開Sessionを作り直す必要はない。

モデル呼び出しの観測をtoken通知とは別の事実として関連付ける。開始/終了/usageを
同じrequest/attemptへ結び、一度だけ数える。親チャットの自己分とすべての委譲先の
自己分を分け、実modelと観測できるreasoning effortで集計する。使用モデルの種類数と
実行回数はその観測から導出し、要求設定だけから実モデルを決めない。
token、回数、モデル/役割内訳のcoverageを独立に持たせる。turnしか公開されない場合の
turn数は代替表示であり、モデル呼び出し数の代用品にしない。最小の実測接続から
取得できない項目を明らかにし、全文トレース収集や別の監視基盤を追加しない。

最上位の表示区分はCodex/ローカルLLMとし、その他providerと実行先未確認も捨てない。
実際の推論先を区分し、呼び出し元クライアントとは別に持つ。CodexからローカルLLMを
使った実行はローカル側だけに計上する。共通観測から区分別に投影し、区分ごとのstoreや
スキル別集計器を作らない。混在する包含集計を分離できなければ区分別の不足を記録し、
分離不能の値をCodexへ丸ごと帰属させない。必要な分類型はU13-01で共通境界に対応付ける。
各区分内に親/子、モデル、回数、tokenとcoverageを保持する。providerの報告値を
同じ料金や計算量へ換算する仕組みは追加しない。

具体的なwire型、provider実行への相関、公開Operation/結果の追加位置はU13-01で
現行APIに対応付ける。CNCFのResourcesは入力・出力のoptional値を持つが、キャッシュ・
推論内訳や包含範囲を現時点で実装済みとはしない。必要な共通拡張はproducerへ明示する。
既存ABIを迂回する文字列キャリアや、スキル固有の集計ファイルを作らない。

最初から実測取得→親子の帰属→保存→完了表示を接続する。fixtureだけの集計器では
主経路の受入れを満たさない。現在のdesktop連携APIが必要な通知を公開していない場合、
その境界を具体的な接続作業として残す。別CLIで得た結果をdesktopの受入れへ転用しない。
一方、非対応のCallerIntegrationでも「未取得」の表示を可能とし、通常の開発を止めない。

最終usageはCallerIntegration側で回答生成終了後に表示する。AI自身が同じ最終回答に確定値を
書く構成に依存しない。通知は既存の実行接続で受け取り、監視用AIや使用量専用agentを追加しない。
集計の再読・再表示は保存済み観測から行い、AI実行や外部業務効果を再生しない。

Phase 11/12のJournal/Evidenceを再利用し、計測のための別store/writerや包括的なログ
収集基盤は作らない。既存producerの保存機能だけで足りない境界は実装時に限定する。
Phase 9のモデル比較・routing、金額算定、予算による実行拒否はこの機能に持ち込まない。
