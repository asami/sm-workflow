# Dependency source revision in existing native owners

Implementation follows the reviewed CC51 dependency-source-revision delivery
proposal. This document does not claim production/installed qualification.

GoalPhaseDependencySourceRevision owns closed versioned business types and the
new describe/adopt direction contract. The existing Decision supersession sum
adds a source-revision disposition. The existing remaining-Plan disposition
dispatcher reconstructs it, and the native continuation walker carries the
direction into ordinary candidate, validation, review and closure. There is no
additional persistence service, resolver, retry registry or candidate store.

Same-source scope succession belongs to this owner as a closed internal value,
carried by the existing candidate and source capture. The native continuation
reconstructs actual later approvals, maps their historical Component workspace
through the adopted direction, and selects an independently declared inventory
successor. The original direction remains the immutable provenance anchor.
Historical capture replay authenticates the captured approvals without selecting
new host defaults. Fresh capture alone selects the current exact declaration.

One effective binding/consumption projection supplies all capture, guard,
staging, validation and downstream binding consumers. Legacy captures omit the
scope field and preserve their encoding. New captures use an explicit version
and retain both the original direction and actual scope proof. The current
candidate owner checks selected-stage admission through existing framework
admission before primary mutation; it does not parse raw host configuration.
Existing managed per-path effects and post-effect verification remain unchanged.

V1 Admission/Capture/AcceptedPrefix remain strict. Revised source data belongs
to optional native candidate fields and a mutually exclusive typed projection.
Old captures are authenticated against the already reconstructed native chain;
new source qualification cannot use an old checks receipt as new validation.
The existing continuation owner may retain the exact predecessor's native
failed-check context when source adoption resumes its repair. Same Session,
Plan, primary base, Step and predecessor admission are required, with current
candidate and validation absent. Explicit candidate `ReviseWork` remains an
implementation generation through the existing controller transition; it does
not need or acquire a repair-only failure context.
The ordinary accepted closure attaches a successor relation without rewriting
the predecessor, primary base, earlier Plan, approved Usage Contract or repair
counts. Historical reconstruction must not retarget old aliases to a new root.

The new closed Guard separates actual committed HEAD/tree, observed full index
tree, status, selected FileIdentity values, excluded identity values and scoped
Git entries. FileIdentity carries actual absence or length/SHA-256. Identity
reads use existing WorkflowFileExecution/File UoW, and Git operations use existing
WorkflowManagedProcessExecution. Guards are repeated observations, not a new
content-integrity permission protocol or an atomic snapshot promise.

Public Record projection may omit absent `Dirty.renamedFrom` and
`StageChange.oldBlob/newBlob`. Their closed readers permit only these optional
omissions, retain explicit-null compatibility, and still reject unknown fields,
missing required fields and inconsistent Git blob/mode combinations.

Attributable staging maps preStageGuard to postStageGuard only through actual
retained per-path stage results and native TreeChanges. Compare selected staged
blobs with adopted content. Other entries and all worktree bytes stay fixed.
Committed mode performs no staging and requires equal guards; an empty diff is
valid only in that explicit mode. Never import Git objects to manufacture an
ancestor or copy dedicated source/JARs over canonical artifacts.

Add host declarations as inactive selections; old defaults, aliases and grants
remain. Actual independently admitted source direction selects the exact new
binding. Consume only the declared primary source route and captured dependency
check workspaces. Match exact installed artifacts and generated ABI through
normal publication and immutable task installation, preserving global selection.

Validation execution, retained-intent reconstruction and existing recovery
readers receive the same authenticated accepted dependency chain from native
traversal. Whole-Phase candidates need not contain a Step source capture; the
accepted chain retains their source-consumption route. Ephemeral recovery
carriers forward that chain without adding it to public targets or stored
proofs. Intent, receipt and program equality checks remain unchanged.

The source-owner regression specifications cover closed codecs, same-status
byte drift, source/exclusion separation, both capture modes, unknown effects,
exact independent direction, restart reconstruction and fresh checks/review/
closure. Existing labelled runtime-test discovery supplies membership; do not
add the explicitly rejected build.sbt registration line.


## Installed consumption successor within existing owners

The existing public Record target has a closed V2 carrying RuntimeSuccession:
original direction reference, actual later approvals and RuntimeSelection. The
selection is an observation of RuntimeConfig.installedRuntimeDistributionC,
including the concrete installation/update/manifest and module/component source
association. It is neither a qualification registry nor new authority. Original
V1 encoder bytes remain unchanged; omitted optional fields are compatible and
explicit null or mixed schema versions refuse.

The existing independent source-revision evidence provider admits the complete
V2 target. The source locator requires an actual unanswered semantic Human, and
the native walker authenticates its original direction and actual approvals.
The walker keeps the original source Direction and carries the consumption
Direction separately; it does not replace historical anchors or defaults. A V2
scope retains both, and all effective source/consumption projections read it.
No extra public Operation, preparation path or persistence owner is added.

The new capture uses the successor's exact observed source guard. Its worktree
bytes stay fixed for that qualified runtime association; managed selected staging
and later freshness still use the existing Git/File owners. Public preflight
and fresh source checks compare the entire current installed association. Legacy
same-image scope behavior and capture replay keep their previous meaning.

Qualification and downstream input ownership remain external: ordinary producer
checks/review/local publication/immutable installation plus independent host
admission establish the actual qualified delivery. Runtime SBT target/program
receipts do not expose its environment. Host owner must bind the existing actual
producer fixture input as well as engine and consumption registration to the new
whole image, and retain the fixed Supervisor artifact and all old history.

## Non-input exclusion succession in the same source owner

The parent-approved bounded extension adds an optional closed ExclusionSuccession
to Target, emitted only in V3 together with the existing RuntimeSuccession. The
source owner derives its parent and exact ordered original exclusions from the
native original Direction, then admits only E0 ++ nonempty A. The independently
declared Consumption must select that exact vector. No raw host parser, new
Operation, storage branch, classification boolean or public DTO field is added.
The existing Record fields carry the versioned nested target.

ScopeSuccessor and fresh Capture have explicit V3 schemas. Their old V1/V2
branches keep their original encodings and predicates; optional exclusion data
is omitted for old values, while explicit null and crossed versions refuse.
The native walker continues to store original Direction and consumption Direction
separately, authenticating the same original parent and actual additional
approvals through contiguous history. Only one runtime successor is supported.

`exclusionsOf(direction, scope)` reads the effective Consumption and
`qualificationOf(direction, scope)` selects the separately retained successor
when present. Codec validity, scope reconstruction, capture guards, source
fact-prefix recovery, per-path staging, freshness and accepted closure use the
same projection. Guard exclusions must match exactly, not form a superset.
Semantic work instructions display the effective binding and exclusions.
Original captures and Direction are never rewritten or qualified by new defaults.

The fresh capture's initial guard is the successor's complete observed guard.
Existing qualified-runtime selected-byte restrictions remain in force. Managed
Git/File UoW owns regular-file, bounds, dirty/rename endpoint and index TreeChanges
admission; selected staging retains its single-path facts and cannot change an
excluded byte or staged entry. Existing recovery authenticates retained prefixes
and keeps ReviseWork/Defer and UNKNOWN semantics without replaying old effects.

The independent host owns non-input semantic assessment for its actual ordered
programs, including helper/plugin/discovery input roots. Runtime enforces the
exact declaration and observation boundary, not a static proof of arbitrary SBT
code. Producer specification fixtures establish only their isolated declared
input boundary. Consumer program provenance and actual adoption remain external.
Normal generator output, focused producer/installed validation, independent
review and LocalPublicationService delivery are parent-owned pending evidence.
The exact Consumption and native guards do not prequalify future source/program
changes. The consumer owner reassesses affected input roots and actual loaded
suite provenance; a missing suite and a zero-test result cannot supply a PASS.

## Committed dependency base within the same native lineage

The explicit V4 target adds CommittedBaseSuccession to this owner. Existing
Target/Scope/Capture versions keep their exact codecs and historical predicates.
Only V4 carries the new optional target field; the encoder omits it for every
older target and the reader refuses null or version crossing. The V4 scope keeps
the immutable original Direction plus the exact separately admitted consumption
Direction, and its capture retains that scope through ordinary native storage.
No operation, public DTO, persistence owner or recovery registry is added.

The native source walker already authenticates same-family runtime succession,
the original parent, genuine later same-Step approvals and the single successor
limit. This extension permits only a new binding revision/native base and the
existing approved path extension. It does not alter logical identity, root,
workspace, branch, checks/routes, requester, Step or acceptance. The original
predecessor guard and primary base remain original history. Native Human evidence
admits the complete observed target before the existing atomic supersession;
separate Advance resumes the same Session/Plan/Step.

The source owner derives four ordered disjoint partitions from the actual typed
TreeChanges between exact CommitMetadata commit/tree pairs. Their union is the
complete delta. The runtime successor predicate additionally checks their
classification against original ownership/E0 and qualified added exclusions.
Background paths consume the selected baseline without becoming edit/stage
ownership or receiving a non-input classification. No historical count is a
constant in the contract.

CommittedEntry distinguishes absence from a regular CommittedObject(mode, blob)
for each effective selected path. The new typed TreeEntries operation uses only
the explicit finite `goal-source-committed-inventory` selection registered by the
host. WorkflowManagedProcessExecution projects it to the thin Git DSL in the
existing GitExec UoW. CNCF owns argv, parser and bounded result interpretation;
SM owns neither raw Git output nor a fallback process. Automatic generic fixture
enum expansion excludes TreeEntries, and the source fixture registers its exact
selectedPaths explicitly along with CommitMetadata.

The V4 observer repeats exact native commit metadata, complete tree changes,
selected entries and ordinary Git guards around managed file/blob reads. It
compares each actual BlobContent.bytes directly with managed File bytes/presence,
then retains the established FileIdentity metadata for legacy compatibility.
The repeated reads are freshness observations, not a new atomic snapshot or
digest/certification protocol. The complete committed rows and delta must still
equal the admitted target during fresh capture and later live freshness.

`modeOf(direction, scope)` and its capture overload join bindingOf, consumptionOf,
exclusionsOf and qualificationOf. The effective committed mode skips source-stage
preflight, intents and results in capture and retained-prefix reconstruction.
Candidate validity requires zero source stages, equal capture guards and clean
selected committed data, even when HEAD/index delta is empty. Historical captures
validate their own binding; fresh current data validates the adopted qualification.
Later selected edits, base movement or mode drift refuse without implicit reversal
or another runtime successor. Existing UNKNOWN rows remain original facts.

The existing native CLI specification adds an explicitly selected installed V4
case: a real selected/background/excluded producer delta is committed between
two bases, the untouched executable and absent selected rows are observed, the
post-adoption candidate acknowledgement is interrupted, and ordinary Advance
collects the exact saved capture with no source stages or duplicate checks. It
also retains an earlier actual UNKNOWN source intent. Current primary work has
a new diff, normal selected checks and independent review, and ordinary Step
closure creates the real primary commit. This covers the supported primary
route; no-new-delta primary completion remains unsupported.

The shared interruption fixture accepts only an optional explicit installed
Bootstrap selection (manifest and pinned CAR), default absent. It supplies
`--no-default-components` and the exact component file through ordinary
BootstrapConfig; InstalledRuntimeDistribution admission is unchanged. The hook
remains specification-owned and child CLI commands use the dedicated installed
executable/image. This correction neither reruns the historical installed001
refusal nor establishes a real consumer operation.
