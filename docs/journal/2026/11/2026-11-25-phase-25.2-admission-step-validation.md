# Routine Step validation through CNCF typed SBT

Decision date: 2026-11-25 (Asia/Tokyo)

Start the validation delivery in [Phase 25.2 P252-05](../../../phase/phase-25.2.md#p252-05--short-step-validation-through-cncf-typed-sbt),
immediately after Phase 25.1. The [Phase 8 cadence](../../../phase/phase-8.md#p8-05-failure-first-repair-validation--selected-2026-11-18)
already calls for focused checks during Steps and FULL at Phase closure.
The ordinary typed SBT `test` still runs the build's FULL suite. Use a short
ADMISSION run and applicable focused checks for routine Step acceptance, with
FULL at Phase closure and when broader coverage is explicitly required.

Give CNCF `sbt_test` and `sbt_test_attempt` a typed `Full`/`Admission`
selector. Keep the existing methods for FULL callers. CNCF owns metadata
selection, ordinary exclusions, execution and typed results. sm-workflow owns
the cadence and the choice of scope for each check. An empty, unavailable or
unverified selection cannot satisfy ADMISSION. Measure test-body time and
compile/setup time separately and reuse comparable evidence where available.

Phase 25.2 retains P252-01 through P252-04 for completion metrics. CNCF can
deliver the selector and its ADMISSION exclusions before the wider legacy tag
migration. Phase 22 can reuse the connected result for the matching Phase 8
requirement. Phase 25.1 and its issued checks keep their current Session,
history, repair counts and results.

## Repository synchronization

The existing impact selector uses focused tests or FULL for program changes.
Apply the [new merge policy](../../../phase/phase-25.2.md#repositorysync-merge-validation)
through the same typed CNCF selector. A merge of non-consumed documents needs
structural and document checks only. A merge that carries over source or
resolves ordinary comments without combining program logic needs ADMISSION.
Combining program logic within a source file or editing it during resolution
needs FULL, including a clean textual merge. Use actual candidate contents and
the existing project input classifications, with retained validation evidence
where applicable. This decision covers merge candidates in both local-main and
remote synchronization stages.

FOCUSED remains the route for a known affected behavior or a bounded fix. A
repair can verify the affected tests first and then satisfy the candidate's
required acceptance scope. Routine ADMISSION adds no separate focused checks
unless there is a concrete requirement.
