# Model choice for strategic judgement and task directives

Decision date: 2026-11-27 (Asia/Tokyo)

[Phase 25.4 P254-06](../../../phase/phase-25.4.md#p254-06--strategic-judgement-and-task-design)
checks rule and template applicability first. If the edit is fully determined,
the runtime applies it and validates it directly. If a known approach still
requires implementation or semantic work, an applicable template provides the
directive directly to the executor. Astra or Sol designs a directive when the
approach requires strategic judgement. Both directive sources use the typed
Task Specification contract, including the acceptance conditions and the
evidence the executor may use. Terra is the usual executor and Sol handles
directives that need its capabilities.

Prefer Astra when the request is eligible for verified free allowance. For the
Codex subscription route, use Sol when free Astra cannot be admitted and the
observed utilization is below a configured ceiling for the actual shared weekly
allowance. Keep headroom for other work. If the ceiling is reached or the
observation is unavailable or stale, select an applicable prepared directive
as the last resort. Apply the same Terra/Sol execution policy based on the
directive's content, and retain any unresolved findings. A separately selected
metered Sol route requires explicit paid authorization and its own monetary
budget. Evaluate design and execution together when comparing cost and quality.

The [Phase 25.5 diagnostic strategy catalog](https://github.com/asami/sm-workflow/blob/main/docs/phase/phase-25.5.md#p255-06--diagnostic-driven-repair-strategy-templates)
feeds the same initial applicability check. It records diagnostic patterns,
repair strategy and validation evidence. Reuse a qualified strategy as a
directive for the current candidate, with Terra or Sol selected by the task.
The candidate runs its own verification. Known, fully determined repairs use
the existing deterministic tools. Phase 25.4 defines and verifies the
connection; Phase 25.5 implements catalog and cache lifecycle.

The [Phase 23 divergence recovery](https://github.com/asami/sm-workflow/blob/main/docs/phase/phase-23.md#bounded-divergence-recovery-p23-05)
continues to require Astra for its bounded replan.
