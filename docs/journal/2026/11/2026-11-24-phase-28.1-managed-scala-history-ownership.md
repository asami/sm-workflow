# Phase 28.1 managed Scala history ownership

Decision date: 2026-11-24 (Asia/Tokyo)

## Decision

For P281-08, the installed native Phase workflow owns routine Scala history
comment updates when it can normalize and check the admitted candidate.
Implementation leaves routine history updates to the runtime. Review and
commit preparation consume the normalization and conformance result for that
same candidate. Changes to the candidate require evidence for the updated
candidate. Interrupted or failed operations follow the existing recovery
contract. Projects and routes without this capability continue to use their
applicable source history rules.

The bundled Phase skill already describes this ownership for its own callers.
The shared directive and the skill loaded from development-workstation need the
same rule so callers and the runtime do not duplicate the work.

## Concrete changes

- In ai-directive `core/RULE.md`, insert the managed-runtime rule at the start
  of the Scala Header Version Update Rules section. Base the local change on
  the directive revision already pinned by the Phase so the unrelated edits
  in the shared checkout remain in place.
- In development-workstation `common/codex/skills/sm-goal-phase/SKILL.md`,
  add the bundled skill's managed Scala source history paragraph immediately
  above the existing recovery section. Commit that paragraph separately from
  existing working and staged edits.
- Select the resulting directive revision through the existing Phase
  ownership and candidate procedures. Verify the two exact documentation
  changes, preservation of existing edits, and agreement between the bundled
  skill and its installed source. The scope is local documentation commits
  and the Phase's directive selection.
