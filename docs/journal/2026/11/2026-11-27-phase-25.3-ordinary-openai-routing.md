# Bring forward ordinary OpenAI routing and daily allowance use

Decision date: 2026-11-27 (Asia/Tokyo)

Schedule [Phase 25.3](../../../phase/phase-25.3.md) immediately after the
current Phase 28.2, ahead of Phase 7.2 and Phase 18. Phase 25.3 can reuse
Phase 25.1 reservation and settlement without waiting for the tool-neutral
validation work in Phase 18.

Phase 25's live review and compiler repair ran in isolated environments.
The ordinary review mapping observed in Phase 25.2 omitted the API route,
and the last review package exceeded the configured bound and went to Codex.
The ordinary Phase 25.2 and 28.2 host configurations did not show the OpenAI
binding and allowance settings needed for bounded execution. These are
dispatch and deployment observations. Actual allowance usage and billing
require separate provider evidence.

Phase 25.3 first qualifies the ordinary route with the existing single daily
allowance, including the necessary fixes to caller policy and runtime wiring.
It then qualifies independent use of the two daily groups. Keep the established
fallback for ineligible packages, explicit free-only admission, and existing
handling of uncertain requests. Confirm actual selection, validation and
Admission through the installed route and retain attribution through the
existing metrics. Keep the current Phase 28.2 Session and accepted results.

The adopted order is Phase 28.2 → 25.3 → 25.4 → 7.2 → 18. Close Phase 25.3
after qualifying the installed route offline. Use ordinary Phase 25.4
development for Phase 25.3's live follow-up, exercising eligible review and
compiler repair as real work produces them. Retain actual usage and reasons
for selection or fallback. Use the cases to inform Phase 25.4 work and decide
the timing of Phase 25.5 from the observed benefit of reusable instructions.
Phase 25.5 has no assigned delivery slot.
