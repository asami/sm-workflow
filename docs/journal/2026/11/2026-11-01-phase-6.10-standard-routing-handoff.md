fallback policy and result admission. The skill-side execution adapter owns the
versioned concrete model/effort table, Codex availability resolution and actual

existing result path. Keep captured policy and resolved assignments on the same
issued work across resume; do not introduce another scheduler or runtime Codex

silently override a resolved assignment. Use supported registered variants or a
supported adapter with the proper execution contract. Do not substitute unrelated
runner roles. Git, SBT, validation and publishLocal remain runtime-owned.

## Availability fallback

For the new standard revision, the explicit finite chain is Luna medium -> Terra
medium -> Sol medium -> Sol high -> Sol xhigh, with Terra high -> Sol high.
Try each candidate at most once, only for confirmed model/effort unavailability
before work starts. The skill-side adapter applies the captured policy and returns
reasons; no separate human confirmation for the same authorized work is needed.
Policy refusals, permissions, malformed mappings, execution failure, timeout,
unknown execution and post-start DECLINED are not model-absence fallback triggers.
Exhaustion is explicit unavailable. Retain old issued fallback semantics as-is.

Do not assume Terra is available merely because it has been released. At this
planning inspection it was not exposed by this chat's agent override list.
Qualify with an available model and record the fallback/availability limitation.
A live Terra run or model comparison benchmark is not a completion prerequisite.
