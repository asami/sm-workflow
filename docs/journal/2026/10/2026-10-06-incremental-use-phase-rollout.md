# Incremental use and Phase 2 carryover to Phase 8

Decision: 2026-10-05; documented through 2026-10-06 (Asia/Tokyo)
Status: planning adopted; product implementation/acceptance not performed here

Subsequent 2026-10-06 decision: the user moved skill creation/connection and
the start of skill-based real use from Phase 5 to Phase 6. The account below
preserves the earlier decision. Follow the current [roadmap](../../../phase/README.md)
and [skill integration revision](2026-10-06-phase-6-skill-integration-boundary.md):
Phase 5 validates the runtime without skills; Phase 6 defines thinking modes and
the skill interface, creates/connects skills and starts use after acceptance.

## User direction

The user wants to build a small usable system and grow it through actual use.
Phase 2 may complete with unimplemented extensions once its practical scope is
usable. Carry those extensions into Phase 8. After Phase 5, start gradual use;
continue using the system while developing Phases 6 and 7 and add functionality
that real use shows is missing. Finish necessary remaining work in Phase 8.
The user has separately scheduled Phase 2 to stop at a coherent boundary.

## Adopted plan

The [roadmap](../../../phase/README.md) establishes Phase 2 -> 5 -> 6 -> 7 -> 8.
Phases 3/4 are orthogonal extensions, not prerequisites for initial use.

- [Phase 2](../../../phase/phase-2.md) and its
  [checklist](../../../phase/phase-2-executable-specification-checklist.md) now
  make practical connected behavior the completion scope. Earlier full-scope
  statements are retained as history and explicitly superseded, not erased.
- [Phase 5](../../../phase/phase-5.md) starts gradual use after practical routing,
  required resource integration and unnecessary-check removal. Its prior mixed
  scheduling references to Phase 4/full server-MCP rollout have been reconciled.
- [Phase 6](../../../phase/phase-6.md) and [Phase 7](../../../phase/phase-7.md)
  continue real use, address use-blocking needs early and keep additions bounded.
- [Phase 8](../../../phase/phase-8.md) owns the remaining runtime/transport/profile
  extensions and discoveries. Its initial map retains original P2 IDs; exact
  remaining behavior is recorded at the scheduled development handoff. Items
  found unnecessary or superseded can be excluded with reasons.

Implementation and Executable Specifications are prepared as connected usable
deliveries. Compile/focused checks remain available during implementation;
integrated acceptance and independent review occur at the behavior boundary,
without a review cycle per helper or repeated unrelated validation after fixes.

dirty implementation and real test evidence. No Goal state, completion checkbox,
test result or runtime capability is manufactured by the scope revision.
This edit does not execute the scheduled stop, resume a task, send instructions
to another chat, commit, publish or release a product.
