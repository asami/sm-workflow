## Default dirty-entry ordering — 2026-10-31

The user clarified that uncommitted changes should normally be committed by their
individual reasons before synchronization. This is B3's standard route, not an
opt-in checkpoint feature. Reuse recorded purposes and acceptance; consult AI only
for genuinely unknown grouping/meaning. Apply existing Step-equivalent checks and
conditional review, commit coherent groups in dependency order, then synchronize
that repository's committed history. No one-file-per-commit rule or blanket FULL.

A purpose may cross files; a file may contain multiple purposes and excluded work.
Preserve meaningful intermediate states and combine inseparable changes with an
explicit reason. Retain completed commits after later failure and continue from
the remaining groups/effects. Do not stash/reset or commit unrelated work to obtain
a clean tree. P611-17 qualifies this ordering and absence of redundant AI/checks.
