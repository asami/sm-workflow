# Managed typed partition context registration

Date: 2026-10-02 (Asia/Tokyo)
Status: implemented; original runtime/package/focused accumulator passed, not Step/Phase acceptance.

## Authority and design

Continue original sm-workflow Phase 2 after the human resume and successful
original accumulator 767 (395/395 examples, 57 suites, runtime preparation and
packaging, exit 0, lock released). Preserve original Goal/Phase scope, authority
bases, independent acceptance reviews, full validation and release. Retained
parent-direct limited recovery/no agents applies, not permission/lock bypass.

Register one explicitly allocated complete context at its exact reference.
Registration is an internal Workflow data boundary, not a skill-controlled
processor or a new public ingress accepting a caller's executable authority.
The actual current authenticated provider/local User or Service principal and
the independently captured exact context-collection Create grant are required.
Host declarations restrict purpose; neither declaration nor raw record is a
storage grant. Load all nine current typed input rows and canonical instance
through the actual incoming call, construct Prepared once, then retain only
that complete data. Reuse the existing private preparation constructor rather
than duplicating its current-fact checks.

The old explicit Start record includes digest-bearing entry assessments; this
new route must not use that decoder/assessment as a fallback. Context Start
reference metadata is inert data here, not proof of the referenced Start,
current human selection, consent, issued work or Completion permission.
Those actual typed Start/issue connections remain prerequisites of production
execution. Registration never advances history, creates a Continuation,
issues WorkOrder or calls old hash semantic preparation.

Retention creates once, observes committed readback and returns only exact
complete equality. An equal later call recovers the original record; a
conflicting payload/revision at that identity is refused without overwrite.
Uncertain Create or unavailable/divergent readback returns transaction-
indeterminate, never success; later explicit calls can observe a committed
row. No automatic retry, claim, application lock, newest lookup or digest.
No writer/provider/lease is retained across calls; Subsystem owns the pool.

## Executable specification

Pure specs: exact create/recovery, same-identity full-data and revision conflict,
malformed retained payload, uncertain Create, missing/failed/divergent committed
readback and subsequent observation without another Create. Use actual private
Prepared construction; mocks of raw bytes confer no storage authority.

Real Service/CLI probes: private input/initial-instance fixture only; do not
preinstall the context under test. Actual configured-local principal and an
independent captured Create grant enable registration/recovery after pool
reopen. Missing/foreign collection grants, untrusted ingress, undeclared current
purpose, foreign instance and complete current-fact drift must fail without a
new row or history change. Confirm fixed identity, one provider/no residual
lease, expired captured-call refusal and prior DataStoreSpace restoration.
Privately mask immediate reads of a real committed Create and recover those
same rows after shutdown/reopen without calling a replacement writer.
The existing Start Operation is only a probe entry; returning no selection
deliberately refuses Start and never establishes genuine human consent.

Run unchanged original runtime/package/accumulated focused suites via the shared
serialized wrapper; new SplitPhase suites join its wildcard. Fresh typed
permissions and scoped native review, no source edits while live SBT, at most
three converging pre-review source repairs for this boundary. Previous repair
histories stay separate; no acceptance gate is narrowed by the new tests.
