# Phase 6.10: Profiles and Two-Endpoint Source Metrics — Development Handoff

Date: 2026-10-27
Status: planning adopted; implementation and live configuration unchanged.
Audience: sm-workflow development and sm-workflow-dev development.

## Adopted direction

Implement [Phase 6.10](../../../phase/phase-6.10.md) after 6.9, keeping
RepositorySync optimization in 6.9 and model evaluation in Phase 9. Provide
standard/cost/quality operating profiles. Standard means the actual existing
configuration and selection rules, not a new recommended model table. Add a
logical profile parameter to sm-goal-phase, with explicit input > config >
standard for new work. Retain captured selections for issued/active work.

The user selected the simplest inexpensive metric: compare source size at Phase
start and close, ignoring intermediate edits. “Source steps” means physical
source lines, NOT the number of Workflow Steps. The earlier development-Step
denominator interpretation is superseded. Count the same authored-source scope
at both endpoints, excluding generated and third-party/output/evidence files.
Keep the scope rules stable while allowing authored files to be added/deleted.

Display start count, end count, signed net increase, already acquired Phase
tokens and tokens per positive net source step. Keep Codex/local usage separate.
For example, 10,000 -> 10,200 lines and 40,000 observed Codex tokens yields
+200 lines and 200 observed Codex tokens/net source step. Always show coverage.
Deletion/refactoring can make this misleading; it is an initial observation aid,
not a quality/productivity score or a progression gate. Zero/negative net yields
N/A, never an absolute-value denominator. Missing data stays unavailable; partial
tokens produce a labelled partial-observation ratio, not total cost.

## Execution order and ownership

1. M1: inventory effective baseline and prove omitted/standard equivalence.
2. M2: wire named selection and stable work-boundary capture through the existing engine.
3. M3: connect two source snapshots and existing usage receipts to deterministic close output.
4. M4: qualify real public entry/output, resume and missing-data behavior; complete focused verification and integrated review.

Use the [specification](../../../spec/ai-operating-profiles.md) and
[checklist](../../../phase/phase-6.10-checklist.md). Reuse existing execution,
Journal/Evidence and usage attribution. Include observed parent/subagent,
failed-attempt and repair usage exactly once; never use account-wide counters as
Phase usage. Keep the observation interval explicit and do not treat the last
invocation as the entire Phase. Phase 13 owns new usage acquisition; 6.10 does
not wait for its full delivery or acquire missing tokens just for this display.

No additional AI calls, model benchmarks, recurring monitoring, per-Step source
sampling or historical log reconstruction. Two mechanical source reads have
small I/O cost; “zero cost” here means avoiding additional AI/telemetry work.
Missing counts/usage must not block accepted work or cause a new close/commit.
Use the final accepted source state before optional synchronization, and reuse
retained endpoints when collecting results again. An active Phase without its
original start count reports that limitation; do not replace it with today's tree.

## Preservation and rollout

Preserve all ongoing work, Session/Plan, accepted results, history, repair counts
and existing verification. Do not restart, resubmit accepted work, reset counters
or replay successes merely to gather metrics. Reuse existing evidence within its
actual scope; new behavior needs its own focused evidence. No source/runtime,
installed skill or active model configuration is changed by this documentation.

Maintain the current configuration for the baseline observation period. Cost and
quality profiles are selectable plans, not activated assignments. Terra adoption
remains a later explicit decision after the November baseline and availability
confirmation; unavailable models must not be silently substituted. Preserve the
parent settings and test/review/repair conditions so future comparisons remain
interpretable. Phase 9 owns that comparison; Phase 7 consumes the mechanism.
