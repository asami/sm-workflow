## Functional boundary

The supported flow is:

1. The public advance Operation resolves managed state, absorbs mechanical
   transitions and returns the actual next semantic request or wait/terminal.
2. The current Codex/host performs the issued semantic work. The skill must not
   choose Workflow stages, reconstruct internal context or select validation
   branches. Actual skill/CLI wiring remains Phase 6.
3. The public result Operation consumes the requested typed semantic result.
   Workflow owns managed commands, effects, native transitions and CAS. AI does
   not gain arbitrary process grants or a relaxed sandbox.

Phase 5.1 verifies this Operation contract with executable specifications.
It does not require sm-workflow to start an AI process, call TextusAI generation,
discover the attached Codex through a new runtime API or prove a provider call
before a valid returned semantic result can be consumed. Real independently
issued Human consent and required review separation are different constraints;
they are not removed by this correction. Optional actual execution observations,
when genuinely supplied and consumed, remain facts rather than fabricated
configuration values or universal completion certificates.
