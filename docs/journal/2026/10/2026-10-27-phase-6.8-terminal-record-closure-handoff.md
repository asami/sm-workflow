# Phase 6.8 handoff: completion records and scoped Terminal

Date: 2026-10-27
Audience: sm-workflow development and sm-workflow-dev development.
Status: user-approved specification/plan update; implementation not claimed.

## Reported case and decision

The user reported: native returned Terminal/completed for selected Stage 12.1
implementation, validation and review, while Phase 12 remained in progress and
GitHub sync was not done. The caller then announced English completion-record
editing and a cncf-commit-execution local commit. This is the reported scenario,
not a newly inspected execution trace or a claim about which commit already ran.

Stage completion need not mean Phase completion, and deferred remote sync can be
legitimate. The gap is required completion-record work escaping runtime closure
after a seemingly final result. Runtime must own that record update and commit,
and the public result must identify the scope that actually finished.

## Implementation direction

Follow [the specification](../../../spec/commit-completion-and-recovery.md#completion-records-and-terminal-scope--2026-10-27)
and [Phase 6.8 C2/C4](../../../phase/phase-6.8.md). Added acceptance is
[P68-23–27](../../../phase/phase-6.8-checklist.md); retain original C/D work and
P68-01–22. Prove the main local route before final installed qualification:

accepted implementation/checks/review -> runtime-owned record preparation ->
optional issued English narrative work -> scoped record application/checks ->
normal typed commit -> durable closure/result -> scoped Terminal.

Reuse a completed implementation commit; coalesce record changes when closure
has not committed yet. No duplicate commit, amend/rewrite or mandatory second
commit. Record actual post-commit identity and final Terminal in runtime evidence,
not in a document required to contain its own commit ID. Use mechanical projection
where sufficient, and no extra AI/review/FULL for already justified completion
facts. Actual semantic changes retain affected assessment. Normal record
preparation is not a product FIX and does not reset/refund prior counts.

Terminal distinguishes selected Stage/Step local closure, whole-Phase closure,
delegated delivery and existing explicitly uncommitted entries. Preserve
test-fix/goal-task contracts. Required records/commit unfinished means unfinished
closure, not lost implementation acceptance. Optional publication/sync statuses
must remain truthful and separate; required delegated publication remains a
delivery obligation. Phase 6.9 still owns clean/dirty sync optimization.

Qualify record-write/commit failure, commit-success/result-loss, repeat collection
and an older early-Terminal episode. Use public same-owner/Session closure
continuation, retaining the original event rather than rewriting it. If a prior
external record commit already succeeded, collect its attributable outcome.
Never re-Start development, replay accepted Submit or repeat successful tests to
reconstruct evidence. No caller-side cncf-commit-execution fallback.

## Preservation and handoff

Keep current work, Session/base/history, repair counters, accepted results and
successful verification intact. This future plan does not direct an unqualified
live migration or add completion obligations to an active Phase retroactively.
Existing defects are handled by their authorized public owner; do not stop
unrelated work waiting for all of 6.8. Reuse existing C1/C2 authority/recovery,
C3 hygiene, D delivery and common Journal/Evidence; add no parallel closure ledger.

Align generated public results/help, packaged/shared caller skills and displays
in C5/D4. The developer must report actual implementation and installed evidence;
this document alone establishes neither remediation nor completed adoption.
