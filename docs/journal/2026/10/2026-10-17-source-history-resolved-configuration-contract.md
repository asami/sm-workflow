# sm-workflow設定とsource-historyの解決経路

Date: 2026-10-17 (Asia/Tokyo)
Status: サイド会話で確認した仕様。実装・検証・受入完了の記録ではない。
対象: sm-workflow Phase 6.1 / P6-HR01・P6-HR04

## 設定の入力と参照

sm-workflowの設定は、共通configファイルとコマンドパラメタのどちらからも
透過的に与えられる。sm-workflowは入力元を区別せず、その実行の
`ExecutionContext.resolvedParameters`から解決済みの値を取得する。

設定ファイルの取得、設定階層、コマンド入力との優先順位の解決はCNCFが所有する。
同じキーが指定された場合は、既存の解決規則に従いコマンド側の値を優先する。
sm-workflowが独自にconfigファイルを探索・読込みしたり、優先順位を実装したりしない。
アプリケーションは取得した値を必要な型へ変換・検証する。

コマンドごとの設定を受け付ける処理は、その呼出しの解決済み値を参照する。
起動時に取得した共通設定だけで固定し、コマンドによる指定を無視する設計にはしない。
コマンド入力の宣言・構文は既存のCNCF機構に従い、任意の未宣言オプションが
受け付けられると仮定しない。

## 正式なプロパティ名

履歴形式の選択に用いる正式なキーは、既存の`sm-workflow.*`名前空間と
ハイフン区切りの命名に合わせて、次とする。

```text
sm-workflow.source-history.style
```

これまでの`sourceHistory.style`という表記は説明上の省略名として訂正する。
正式な外部プロパティ名にはしない。関連する規則設定も、同じ
`sm-workflow.source-history.*`の名前空間と既存の命名規約に従う。
個々の追加キーや提供形式は、この記録では確定しない。

共通configでもコマンドパラメタでも、同じ論理キーを用いる。
この記録は新しいCLI構文や別名の互換契約を追加しない。

## source-historyの動作

| 解決された値 | 動作 |
| --- | --- |
| 未指定 | 既定値`none`を使う |
| `none` | 履歴用の規則解決、対象ソースの読取・更新・検査・警告を行わない |
| `goldenport` | 設定された外部規則に従い、浅海式の決定的な履歴整備を行う |
| 不正な値 | 設定エラーとし、別の形式や既定値へ黙って代替しない |

`asami`という別の形式選択は追加しない。`none`でも通常の意味的なソースコメントの
記述・レビューは無効にならない。

`goldenport`の実際のタグ、日付形式、履歴圧縮方針等は、設定された外部規則から
取得する。外部規則が解決済みconfigurationとして供給されるなら、その値を使う。
sm-workflowが別途JSON規則ファイルを読み込むことを前提にしない。
選択した規則が未提供・解決不能・不正なら、設定／ツールのエラーとして扱う。
規則をアプリに固定実装したり、AIへ履歴編集を依頼したりして代替しない。

## 設定取得とソース操作の責任分担

| 処理 | 所有する経路 |
| --- | --- |
| 共通configとコマンド入力の解決 | CNCFの既存configuration／parameter機構 |
| 解決済みの形式・規則の取得、型検証と決定的な適用 | sm-workflow。呼出しのExecutionContextを参照 |
| 履歴整備対象ソースの読書き | 既存CNCF File内部DSL。権限確認と実行は現在のUoW内 |

File DSLを使うという説明は、整備対象ソースの操作を指す。
configurationをアプリ独自のFile DSLローダーで再構成する意味ではない。
今回の修正はsm-workflow内に閉じる方針であり、外部規則を使うという理由だけで
goldenport-coreやCNCFの変更を必要条件にしない。

[外部provider案](../../../design/source-history-external-provider.md)を扱う次の通常の
計画更新時に、この設定経路・正式キー・責任分担を反映する。
外部JSONファイルの独自読込みを前提にした案は、この仕様に合わせて見直す。
このjournalはproviderの提供形式や実行可能性が確定・検証済みであることを表さない。

実装時には、共通configだけでの指定、コマンド側の同じキーによる上書き、
既定の`none`、明示的な`none`による無操作、規則不在／不正時のエラーを、
既存の通常コマンド経路で必要な範囲だけ確認する。
履歴整備の実行・検証・レビュー・commitは、既存のP6-HR01/04とPhase 6.1の
手順に接続し、新しいレビュー工程を設けない。
