# SplitPhase native-bound scope restoration

This internal preparation contract supports the existing public advance
Operation; it adds no externally selected processing stage.

1. A completed source is constructed only by the managed scope owner after
   checking the actual authenticated owning advance call/command, original
   participant, independently read Start/context/facts/documents, immutable
   first checkpoint, exact retained WorkOrder, canonical completion, closing
   result and full committed history prefix.
2. A pure completion projection cannot construct that source. A raw passive
   snapshot or admitted semantic reply cannot restore an executable frontier.
3. Restoration loads the effective saved shape/boundary/partition/planning data
   and copies the complete cached enumeration and candidate views. It does not
   call enumeration, allocation policy or candidate projection again. Built
   bodies/local transfers, semantic gaps, repository and numbering Decisions
   remain in order and retain their identities. Numbering data must still load
   as the exact saved numbering Decision.
4. Projecting the restored requirement back to a passive snapshot must equal
   the complete original checkpoint before scope application is prepared.
5. Known scope application consumes the actual completion's admitted reply.
   Enriched retains every original candidate; DecisionNeeded retains a genuine
   Human need. Neither preparation publishes documents, appends history,
   returns successful public advance/WAIT nor declares Terminal.
6. Repeated owning-call observation and physical SQLite reopen without
   allocation policies preserve the original first root/native state and
   restore the same effective frontier/result. Wrong Operation or participant,
   missing/crossed native provenance and changed same-reference facts reject.

Executable evidence: the two genuine scope completion scenarios in
`SplitPhaseManagedPlanningCheckpointSpec` extend their actual Service/CLI issue
and completion with explicit test-only owning advance preparation observations.
Existing pure `SplitPhaseScopeProjectionComputationSpec` covers frontier and
scope computation. Both are currently unexecuted for this new subject. Broader
origin/failure/public publication/recovery evidence remains an open Phase gate.
