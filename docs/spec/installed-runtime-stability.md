# Installed runtime stability

`DEV-SBT-RUNTIME-CLOSURE-001`, `P64-runtime-distribution-stability@3` qualifies
the parent-adopted installed-runtime lifecycle through the actual installed
command and ordinary typed SBT admission. Mutable SNAPSHOT replacement is the
probable incident cause; publisher attribution is not established.

`NativeGoalRuntimeStabilityCliSpec` is an explicitly selected `@DoNotDiscover`
executable specification. It requires absolute properties
`smworkflow.spec.installedCommand` (the actual installed launcher),
`smworkflow.spec.runtimeRoot` (the isolated registered installations root), and
`smworkflow.spec.sbt` (the normal SBT executable). The parent prepares and
selects an actual generation through the authorized registered producer's normal
`publishLocal`; the spec performs no publication, registration or activation.
Normal SBT caches, repositories and sbt-native exclusion remain in use.

The spec creates a new test-owned host, repository and Session under
`target/sm-workflow/work/validation-recovery/`. Existing public fixture
Start/Advance/Submit establishes one accepted semantic implementation. It then
uses the installed executable with `--host` and `SM_WORKFLOW_INSTALLATIONS` to
execute normal `advanceGoalPhase`. The selected check is one typed Test owned
by the normal UoW. Its ordinary consumer build enables
`org.goldenport:sbt-cozy:0.1.18-SNAPSHOT`, depends on
`org.goldenport::goldenport-cncf:0.5.3-SNAPSHOT`, and contains one ordinary
ScalaTest source. Its ordinary ScalaTest 3.2.19 dependency is declared in Compile
and inherited by Test, matching the actual application graph. It needs no CML, replacement Test task, product main or
unmanaged classpath. The consumer requires the concrete manifest property
supplied by typed SBT admission; the plugin's required support prerequisite
must complete before the original Test.

## Producer-selected application closure (CB-RUNTIME-V3-003)

The registered producer's normal publication owner passes its actual ordered
SBT `Compile / dependencyClasspath`, with moduleID and artifact metadata, into
the runtime-update preflight. The selected application graph owns versions and
classifiers: ScalaTest 3.2.19 remains selected even though the CNCF root alone
would normally resolve 3.2.10. The updater performs no independent root-only
resolution and copies the selected actual files to ordered `runtime/NNNN.jar`
entries, along with that publication invocation's actual CAR.

Registration stays `cncf.local-application-update.v1`. The request is explicitly
`cncf.local-application-update.v2`, with required ordered `runtime_modules`;
each closed object has exactly `coordinate` and `source`. Coordinates are
`organization:name:revision` or `organization:name:jar:classifier:revision`,
derived from SBT metadata. Sources are canonical absolute existing independent
regular JARs. Missing metadata/root, unmanaged or non-JAR inputs, unsafe parts,
duplicate coordinates/sources and conflicting revisions reject. Producer
preflight happens before the publisher; updater admission and materialization
recheck the vector. Strict installed-runtime mapping is unchanged.

Old v1 requests reject explicitly. Known-failed-runtime-stage recovery requires
the original v2 request through the same strict reader and preserves its exact
ordered module vector; it never reconstructs old requests from current
dependencies, rewrites history or replays the publisher. Installed manifest
`cncf.installed-runtime.v1` and composite result
`cncf.local-application-publish.v1` remain unchanged. The registered helper is a
separately installed fixed copy; only explicit parent promotion after review
and tests replaces it at that same filename, preserving the previous copy.
There is no automatic helper refresh or registration migration.

Each new fixture requires the selected generation to contain ScalaTest 3.2.19,
with no ScalaTest 3.2.10 module. Its actual Test records and checks
`org.scalatest.wordspec.AnyWordSpec` class and resource origin against the
selected `scalatest-wordspec_3:3.2.19` JAR, alongside CNCF/Core origins. Historical
retained 3.2.10 captures keep their original two origin rows and are not new
application-closure evidence. The default remains one fresh isolated episode;
overlap and retained branches require explicit selection.

An incompatible target Compile/Test dependency graph still fails strict
version/classifier mapping. Helper tests and matching metadata alone cannot
qualify the closure: actual staged bootstrap and the actual ordinary UoW Test
remain parent-owned acceptance requirements. No existing successful episode or
real Phase Session is replayed by this repair.

## Target project binding (CB-RUNTIME-V3-004)

R1. The installed CLI's own runtime and the target project's build are separate
scopes. Each admitted workspace selects `cncf.sbt.runtime-binding.<WorkspaceId>`
from resolved configuration. Missing configuration, or the exact string `project`,
uses ordinary project Compile/Test/TestOnly without adding installed-runtime JVM
properties or `cozyCheckInstalledRuntime`. Ordinary workspace and capability
admission still applies. This mode does not require sbt-cozy in the target build.

R2. The exact string `installed` selects the strict installed-runtime profile.
The pinned-runtime fixture adds
`cncf.sbt.runtime-binding.sm-workflow-repository-validation-1=installed` to its
new owned host's existing JSON configuration before starting the installed CLI.
That profile requires a concrete valid manifest and host-declared sbt-cozy
support; invalid configuration or missing support never retries in project mode.
CLI bootstrap continues to validate its own installation in both modes.

R3. `NativeGoalProjectBuildCliSpec` uses the same three required absolute
properties and normal managed fixture/bootstrap, with two fresh owned hosts
under `target/sm-workflow/work/validation-recovery/`. E1 admits one ordinary
Compile on a bare Scala 3.3.8 build and verifies its actual compiled class.
E2 admits one ordinary Test using a real ScalaTest 3.2.19 source and verifies
its semantic input, one execution marker and successful typed Test receipt.
Both leave the runtime-binding configuration absent. Neither target has
`plugins.sbt`, CML, a substituted task, product main or unmanaged app classpath.
Finite onLoad observations record the actual SBT PID/commands and absence of
both installed JVM properties. Actual CLI class-load captures bind CNCF/Core
origins to its selected copied installation. Fresh ordinary Continuation retains
Review, receipt, Plan, base, history and counters without another SBT execution.
These are authored obligations; the parent owns their actual execution.

The SBT 1.9.7 onLoad capture must contain exactly `sbtPopOnFailure`,
`resumeFromFailure`, `notifyUsersAboutShell`, `iflast shell`, followed by the
sole selected `compile` or `test` task. No unknown prefix or command is ignored.
The initial qualification failure at this assertion remains retained even when
the actual operation already produced ReviewStep, a terminal exit code of zero
and a successful typed receipt.

To qualify those existing successes without repeating them, explicitly supply
both absolute properties `smworkflow.spec.projectBuildCompileRetained` and
`smworkflow.spec.projectBuildTestRetained`. Each must name its canonical
immediate child under this repository's validation-recovery work root, with
the corresponding `ordinary-project-compile-` or `ordinary-project-test-`
prefix. Missing paired input or a bad path rejects without creating a fixture.
The branch decodes the original `0.stdout.json`, `0.stderr.log` and
`0-class-*.log` into captured business/events/origins, without inventing an OS
exit status. Host checks, the captured operation/Session, actual terminal event
and retained typed receipt must agree. The actual retained intent supplies the
history-prefix baseline; every shared success assertion remains applicable.
Only a fresh ordinary Continuation runs, using the next unused log ordinal.
It must preserve the complete record, intent/result, Plan/base, counters and
execution markers, with no retry or successor intent. This branch never starts,
submits or initializes the old Session or repeats its successful SBT check.
The default branch continues to create fresh fixtures for future independent
qualification. Parent execution and independent review remain required; this
test-only correction supplies no publication or new product-runtime evidence.

## Pinned-runtime lifecycle observations

The actual Test records loaded CNCF/Core/ScalaTest `CodeSource` locations and class-resource
URLs after its optional gate. Each must refer to a regular runtime JAR in the
concrete admitted generation. A fixed test-owned `JAVA_TOOL_OPTIONS` class-load
log observes the installed CLI JVM's actual protected Goldenport/Model class
origins. Every observed protected origin must belong to the pinned generation;
manifest IDs alone are insufficient. A JVM-generated Lambda may name its host
class as its source only when its synthetic name identifies that exact host and
the same capture contains an ordinary file-origin entry for that host in the
installed generation. Arbitrary non-file origins still reject. Logs, PIDs, typed captures, gate files and
origin records remain in the owned work root, outside source control.

Fresh installed Continuation returns the same pending independent ReviewStep.
The read-only recovery-description operation correctly refuses a resolved
successful check. Both calls must leave the complete native record and retained
intent/result unchanged, with no second Test, successor ordinal or retry.
Assertions retain the accepted history prefix, selected Plan, original base,
candidate, receipt, repair counters and all definition metadata. ABI definition
metadata is compared explicitly across classloaders. The spec supplies no review
acceptance, commit, Phase closure, recovery permission or real-Session authority.

With `smworkflow.spec.runtimeOverlap=true`, also supply an existing absolute
`smworkflow.spec.runtimeControlDirectory`. The old actual Test writes its owned
ready marker before explicitly loading the protected classes/resources. The
outer spec verifies its child ownership and writes `test-ready.json` once in
the supplied control directory, including the exact isolated host, Session,
installation and Test PID. The parent then runs the authorized registered
producer's ordinary `publishLocal` concurrently through its normal runner.
The spec waits at most 900 seconds for natural selection of another generation,
then releases its old gate. Old Test origins must remain G1; fresh installed
calls on the same old Session must retain its success without another check.
A new test-owned Session admits one necessary Test, whose CLI and consumer
origins must use G2. No independent producer SBT is launched by the spec.

An explicit post-success qualification continuation is available through the
absolute `smworkflow.spec.runtimeRetainedReady` property, naming the original
`test-ready.json`. It selects the retained-success branch instead of creating
another G1 episode. The marker must have the expected kind and bind an existing
canonical host directly under this repository's
`target/sm-workflow/work/validation-recovery/`, the configured installations root,
the concrete original manifest and generation, and the exact one-entry Test PID
record. The original expected manifest/runtime files must match that generation.
The original `0.stdout.json`, `0.stderr.log` and `0-class-*.log` captures must
contain the same Session's actual ReviewStep, one Test start and its successful
terminal event, plus the concrete G1 class/resource origins. No OS exit status,
native result or pre-Test snapshot is manufactured from those files.

This branch requires G2 to be currently selected. It reads the old current
record and actual retained `check-intent-0` record through the existing fixture;
the actual intent history is the retained before-effect baseline. Fresh installed
G2 description and Continuation must preserve the original ReviewStep, record,
intent/result, candidate, Plan/base and counters with exactly one old Test PID.
New captures use unused ordinals and preserve the original captures. Only a
separately new G2 test-owned Session performs a new necessary Test. The branch
does not repeat the old Start, Submit or successful Test, publish, activate,
release an old gate, rewrite native records or claim a synthetic earlier
implementation snapshot. The parent retains the original publication/activation
and process-completion evidence and its original scope limitations.

All lifecycle waits are finite: gate readiness 300 seconds, activation/gate
900 seconds, owning-UoW Test 1,200,000 milliseconds and installed CLI
1,500 seconds. Cleanup releases owned gates, tracks only descendants of each
owned CLI Process, terminates remaining owned children and waits for their
termination. There is no process scan, machine-wide lock or cache relocation.

Authorship is not execution evidence. The parent owns focused execution,
actual producer publication/activation, independent review and acceptance.
Passing helper/mock tests or compilation alone cannot qualify this contract.
The optional overlap case requires an actual successful producer invocation and
its retained composite publication/update result. A changed generation ID does
not prove different producer bytes or an API/marker difference; that stronger
claim requires actual distinct producer inputs and observations supplied by the
parent. This consumer example does not exercise failed/interrupted publication,
staging/admission failure, lost activation acknowledgement, missing plugin/module
support, unsupported external component closures, process-started failure or
unknown-result branches. Those remain separately selected evidence obligations.
Build-time plugin/launcher/generator replacement is not covered by the runtime
binding. Existing E8/E9, prior successful fixtures and the real development
Session are not replayed or promoted into runtime-distribution evidence.

## Checked child launcher classpath (P64-CHILD-CLASSPATH-01)

The installed-profile SBT prefix `cozyCheckInstalledRuntime` validates both
Compile and Test dependency scopes against the concrete selected manifest and
then refreshes `target/cncf.d/runtime-classpath.txt` from that same invocation's
ordered `Compile / fullClasspath`. The export uses the existing strict binding:
source application product paths and nonselected dependency entries retain
their order, selected dependencies name the exact copied installation files,
and duplicate absolute paths are removed in their first-occurrence order.
The installed application CAR does not replace source application products.
The unchanged `bin/launcher` consumes this prepared export during the original
ordinary Test or TestOnly.

Both dependency checks and full-classpath binding must succeed before any
export write. Missing required manifest configuration, invalid installed files,
absent selected modules, and version or classifier mismatches reject without
rewriting a previously valid export. The export never reuses old file entries
or reconstructs module selections from manifest source paths. Replacing or
deleting original mutable dependency sources does not change the copied paths
selected for the child launcher.

Without a selected manifest, this prerequisite leaves existing exports and
absent exports untouched. The explicit `cozyRuntimeClasspathFile` task retains
its existing behavior. `InstalledRuntimeClasspathSpec` supplies executable
examples for ordered refresh, mutable-source independence, rejection before
write, and ordinary project-mode preservation. Parent-owned focused execution,
plugin publication and actual installed-profile ordinary Test qualification
remain required; these authored examples do not establish their execution.
