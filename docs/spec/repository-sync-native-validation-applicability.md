bindings, actual source revision and receipts. It stores no complete policy or
policy identity/revision witness. Repository progress v3 writes these facts.
Its v1 reader extracts the actual mode/reason/check plan from the former policy
container and ignores its absent or unusable identity/revision metadata. It
does not recreate a Policy, compare a declaration, rewrite a row or invent a
check result/permission. The v2 reader consumes its already selected facts.
Missing actual old check facts remain an explicit error.
New-format fields cannot reintroduce the removed policy witness. Readers admit
declared nested structure and actual types, not a re-encoded body certificate.

Recovery consumes the original selected check plan and reason. Current host
bindings must resolve the selected check identity/ordinal and the skip/required
mode must remain semantically compatible. A different policy name/revision/
explanation, declaration ordering or extra unselected binding is not a refusal
or reason to execute another check. Missing/replaced selected bindings and an
incompatible product-test skip/required mode are real incompatibilities, not
metadata stability checks. The ordinary runtime still admits each actual fixed
program and its current execution permission; AI cannot supply commands.

Validation matches actual native candidate/index/parents/tracking and selected
source frontier, not a complete copied observation or earlier history.
Completed validation admission is shared with nonmerge convergence selection,
including real receipt coverage and success. Actual worktree conditions, state,
CAS, scope, permission, failure/indeterminate outcomes and unknown-effect
non-replay remain. Separate Git observations are not an atomic snapshot.
