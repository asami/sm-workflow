# Goal Phase current inventory continuation

AUTO-FILE-GP-01 fixes automatic file inventory for the retained current Step.

R1. An authentic completed ImplementStep or current-Step RepairStep may return
`decision-needed` with its actual complete raw `planRevision` and causal reason.
Only a fresh revision and literal append to the current Step's ownedPaths may
change. Repository, Component, purpose, Usage, raw/effective acceptance, checks,
dependencies, operations, all other Steps and accepted prefix remain exact.
Finite concrete path data has no arbitrary file-count ceiling. Relative-path,
workspace, capability and actual-effect admission still applies. A registered
candidate prefix alone grants no foreign Component or operation authority.

R2. The original selected execution is standing authority for this same-purpose
inventory. Before issuing a file-only Human question, native continuation writes
one adjacent mechanical receipt with decision `AUTO original-purpose inventory`,
selected paths, actual semantic work/result references and original causal reason.
It preserves the original result and every old issue/receipt/history entry, base,
accepted Step, repair count and control. Only the current inventory Plan revision
and normal generation advance; fresh candidate, checks and independent review
remain necessary. No Human answer or external grant is fabricated.

R3. Only the native history walker constructs a Source from contiguous actual
issue, suspension and completion. Review, dependency/diagnostic changes, changed
requirements/ownership/acceptance/operations and unknown or executing work remain
actual concerns. Fixed hosts retain their explicit capabilities. Standard runtime
appends invocation-local candidate paths, preserving prior staging ordinals and
closed-Step selections, and authenticates every receipt during history restore.
Malformed retained receipts fail; they never become absent-source fallback.
The result must contain the inventory proposal and its reason with no unresolved
adjunct judgment: findings must be empty and every acceptance, issue, review,
completion, repair-source, dependency or diagnostic adjunct must be absent.
An optional valid fix assessment is concern-free only when requirementChanged
and contractChanged are both false and convergence is PROGRESSING. Its actual
metadata remains retained. A null Option is invalid, never absence. Mixed
findings, BLOCKED/STALLED/REGRESSING assessments, requirement or contract change
claims and other reports remain Human judgments with their actual semantic
result and history intact; automatic inventory never discards or supersedes
those judgments.

R4. An existing unanswered exact inventory-only question may be superseded by
the ordinary native DecisionSupersession adapter under the same standing purpose.
The question is retained without an answer. Mixed judgments and accepted Defer or
Cancel remain retained and unchanged. Existing manual RemainingPlan and external
InventoryAuthority receipts remain readable, with no backfill or invented grant.
The existing all-closed Phase repair inventory continuation retains its owner.

E1. An unchanged existing build file and a new concrete source file enter native
current-Step inventory automatically. Reopened ordinary commands retain original
purpose, acceptance, base, accepted prefix, actual old semantic result and repair
count; subsequent candidate/check/review/Step closure includes the source file.

E2. A proposal changing purpose, acceptance, another Component or future Step
ownership remains a Human concern; executing/unknown semantic work cannot be
selected by the inventory helper. An otherwise exact inventory proposal with
unresolved findings or another adjunct judgment also remains Human.

E3. A reserved current repair preserves its existing accounting; unsafe,
duplicate and overlapping paths refuse independently of finite inventory size.

E4. All-closed Phase repair inventory remains with the existing Phase repair
continuation; the current-Step selector refuses that distinct source.

Executable specifications: `GoalPhaseCurrentInventoryContinuationSpec` and
`NativeGoalCurrentInventoryCliSpec`, selected by `AUTO-FILE-GP`. The latter uses a
small isolated normal host and the same installed CLI when
`smworkflow.spec.installedCommand` is selected. All semantic and independent
review/closure evidence in that fixture is explicitly specification-owned.
