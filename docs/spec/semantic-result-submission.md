# Semantic result projection

A worker can return short immediately useful `outcome`, `summary`, `resultType` and `resultResource` values. The Resource names the caller-owned result artifact. Source references and actual execution attribution remain independently supplied to normal completion; a reference is not acceptance. The saved artifact uses the exact four keys `schemaVersion`, `resultType`, `workResource` and `result`, with schema `sm-workflow.public-worker-return.v1`. Its result is the complete public DTO and its work Resource is the exact original retained-work Resource; the original issued context remains unchanged for native Submit. Private native state/result codecs are unsupported.

`NativeWorkflowPreparationService.projectSemanticWorkResult` takes the exact `sm-workflow-work:` Resource and the result file Resource. Its default summary reports outcome, summary, type, next submit operation, submit Session and both source Resources. Explicit `public-result` returns the complete result as `resultJson` text alongside those fields, preserving opaque nested keys through CLI egress. The original authenticated retained-work reader and the complete public reader remain authoritative. The obsolete full-context draft is refused. A malformed, crossed, unavailable or unsupported input fails without Submit; resource failures have no full-body fallback. The normal `complete` caller acquires `public-result` and writes that JSON text unchanged to an output artifact for the existing `resultResource` Submit. Direct inline results remain supported.

This describes product source readiness only. Installed caller adoption, validation and independent review require their actual receipts. The separate terminal saved-versus-inline response projection mismatch remains pending.
