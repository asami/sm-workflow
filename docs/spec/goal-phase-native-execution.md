# Native Goal execution disposition

This contract connects semantic Goal classification to fresh native WorkOrder
issuance. It consumes the delivered CNCF execution-profile resolver and existing
WorkflowProtocolV1 observation admission. Configuration and specification-owned
observations establish no genuine installed executor/provider execution,
independent review provenance, permission, Step acceptance or Phase acceptance.

The supported [native host execution handoff](native-host-execution.md) consumes
the actual public issued context and original canonical snapshot, retains a
finite host Session and projects only actual final COMPLETED observations into
normal Submit evidence. It does not install a provider or change Goal policy.

## R1 — Semantic and operational source responsibility

The selected Plan supplies semantic classification, ReasoningClass, reasoning
level and assigned review responsibility. Trusted host Component initialization
parameters alone supply concrete profiles, the current executor descriptor and
execution preferences. Named business inputs and AI semantic results select none
of those operational values. The host obtains the descriptor from its actual
executor runtime; parsing a declaration proves no observation. Do not derive an
AI context from a CNCF process ID, authenticated participant, chat/session/workflow
ID, profile identity or model text.

## R2 — Optional canonical configuration pair

The ordinary canonical Component hierarchy resolves `workflow.execution.profiles`
through CNCF `WorkflowExecutionProfileParameters`. Its delivered exact-field
decoder and mapping contract remain authoritative. The companion optional key
`sm-workflow.execution.origin` consumes this explicit shape:

```json
{
  "schemaVersion": "sm-workflow.execution-origin.v1",
  "current": {
    "contextIdentity": "explicit-runtime-context",
    "profile": {
      "identity": "diagnostic-profile-identity",
      "provider": "concrete-provider",
      "model": "concrete-model",
      "controls": { "reasoning-effort": "high" }
    }
  },
  "preference": { "forceInline": false, "isolateContext": false }
}
```

The origin key accepts a structured ConfigurationValue object or a JSON string.
Schema, current descriptor/profile, controls and both Boolean preferences are
required consumed members; absent/null/invalid values fail through Consequence.
CNCF validates canonical descriptor/profile strings. Unused origin diagnostics
stay inert; alternate member names, sources, private merge rules and inferred
defaults are unsupported. Both keys absent preserve the existing unconfigured
composition. Exactly one present, null options or invalid Origin are errors.
Both absent supplies no evidence of successful mapped execution.

## R3 — Fresh issue resolution

`GoalPhaseNativeWorkContinuation.issueAssignedC` first loads the owning issued
row. Only its missing-row branch, after candidate preconditions and immediately
before native suspension, calls `GoalPhaseNativeExecution.bindIssuedC`. It accepts
an actual canonical WorkOrder and uses CNCF `mapping.resolveC` to bind only the
requirement disposition. Handle, request, presentation and semantic requirement
members remain unchanged. Matching current profile may select Inline/Optional;
different profile or context isolation selects Delegated/Optional. Required review
selects Delegated/Required even for matching model/profile. Forced Inline with
review or isolation, an absent class or already selected disposition fails.

Preparation and predecessor/Human/completion reconstruction stay semantic. All
fresh ImplementStep, RepairStep, ReviewStep and ReviewPhase issues, including
Human-resumed generations, share this branch. Resolution makes no provider call
and grants no command or closure authority. Concrete resolver output is
operational; this contract retains no concrete provider-dispatch plan in
Workflow state. The host separately retains its original concrete selection
under the host execution handoff.

## R4 — Saved issue reuse

Pending, reconstructed, completed and earlier Human assignments consume the
actual saved interaction selected by the native issued-row lookup. A later
mapping or origin cannot reroute that issue, require its old class to remain in
the current mapping, or replace its disposition with a regenerated default.
The declaration is selected when each host is constructed. Editing its config
file does not modify an already constructed host. Later fresh issues consume
the explicitly selected later host snapshot.

## R5 — Existing storage and completion owners

Only the canonical selected requirement disposition is persisted in existing
WorkOrder storage. CNCF's separate versioned host Session artifact holds the
concrete selection and actual observations under the host's resource binding;
it introduces no Goal profile store, task registry, public DTO/schema extension,
migration or second admission engine. Existing native
completion consumes the saved requirement and generated `executionEvidence`
observation: placement and origin must match, Inline executor equals origin,
Delegated executor is nonblank and distinct, and required independence remains
distinct. Missing or contradictory observation fails native admission.

The normal named Submit still requires its canonical target, type, CAS,
completion contract, participant and separately prepared independent review
evidence. Its typed accepted/message acknowledgement does not issue next work.
The caller separately Advances through current validation, Human decisions,
Step/Phase authority and repository child closure.

## R6 — Evidence limits and compatibility

Configured identity/model strings and resolver success are neither execution
observations nor permission. Specification-owned descriptors/results exercise
actual native structural admission and fixture progression only. Existing two
unconfigured Goal programs retain absent disposition and all native checks,
review/Human evidence, owned commit authority and child convergence obligations.
The additional mapped program is no acceptance of this real Phase.

Ordinary commands, the single normal FQN client Start connectivity smoke,
business parameters, skill procedures and packaging remain unchanged. Genuine
installed tasks for all three families, modes, actual provider observations,
replacement/fallback routing, participant evidence, independent bounded Goal,
Effective Acceptance Boundary and original acceptance/release remain required.
Primary aggregate full validation belongs to PHASE-6.3.

## R7 — Applicable security evidence

Select a missing check only for an affected adopted security requirement whose
applicable evidence is insufficient. Reuse delivered producer guarantees under
their conditions. CNCF107/Cozy83/CBD16 remain planned; imported plans establish
neither provider availability nor implementation/security PASS and create no
blanket wait. This contract adds no security engine, scanner, separate review
stage or security matrix. Existing Phase 6.1/6.2/6.3 responsibilities remain.

## Executable specifications

`GoalPhaseNativeExecutionSpec` covers E1 (R1–R2: canonical structured/string
origin, inert diagnostics, absence and malformed consumed input), E2 (R1,R3:
placement, independence, contradictions, generic descriptor observations), E3
(R3–R4: unchanged business identity/contracts, legacy behavior, selected and
non-WorkOrder refusal), and E4 (R2,R5–R6: declaration/default and normal factory
pair admission, observation required despite valid configuration names).

The one mapped `ThreeWorkflowGoalOperationSpec` whole-Phase program covers E5
(R1,R3–R6): actual saved first issue under a revision2 mapping without its class,
subsequent fresh mapping selection, completed predecessor walking, repair and
Human resumption, public issued context, and separate Submit/Advance. Each
independent runtime boots from its explicit specification configuration; the
old first Inline origin remains saved while new work uses revision2. E6
(R3–R7) submits missing and contradictory fixture observations before each
mapped semantic completion, asserts no native state/history/suspension change,
and retains the additional separate independent-review-evidence obligation.
Mapped evidence now comes from `NativeWorkflowHostExecution` using the actual
public Advance context and specification-owned actual descriptors, retained
per continuation through pending redisplay and Human episodes. E7 verifies first
Routine INLINE without a mandatory child; E8 keeps the original host selection
under later missing-old-class configuration and stops noncompleted operational
branches without Submit/Advance. E9 records first ReviewStep UNAVAILABLE and
its single configured alternate COMPLETED while retaining the same native
pending reference, then still requires independent host review preparation.
Representation-negative submissions reuse that completed observation. Valid
fixture observations permit ordinary native progression only. These examples
make no claim of genuine executor provenance or installed acceptance.
