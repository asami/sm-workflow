## R1 — Saved candidate facts, not a host-path declaration witness

Native candidate Payload/new v2 writes no longer carry hostPaths as a copy of
the complete staging declaration. The v1 reader ignores that obsolete field,
including absent, malformed, null and non-string values, without rewriting a
record or creating authority. It reads actual selected/staged paths, candidate
Git references and observation facts. The active selected paths must still be
permitted by the current Step ownership and installed staging programs; an
unselected extra host path is not a restart conflict.

The reader checks declared field structure and decodes actual typed data.
It does not re-encode an entire payload and compare bodies as an admission
certificate. Optional absent fields may decode normally. Undeclared execution/
authority fields and malformed current data still reject, including nested
candidate fields. Selected intent/result frontier checks use actual paths,
slots and state, not equality of their complete proposed/previous payloads.
A retained effect intent without its recorded result is never automatically
replayed. Native branch/head/tree and ownership preconditions are unchanged.

E1: GoalPhaseNativeRetentionApplicabilitySpec covers new output without hostPaths,
v1 reads with obsolete values, absent optional facts and actual shape/type errors.
These are codec cases, not an old physical SQLite migration claim.

## R2 — Required check resolution, not complete policy/receipt equality

Native validation Payload/new v2 writes remove the complete policy witness.
Actual selected check identities/program bindings and actual result facts remain
recorded. Old v1 policy fields are discarded without requiring a revision,
complete policy or body match. Current required checks resolve through their
actual installed bindings. Missing checks or incompatible selected bindings
still reject; unselected bindings or policy metadata changes do not prevent
consuming the saved outcome. This is executable applicability resolution, not
replacement of a body hash with policy identity/revision equality.

Validation codecs perform declared structural/type admission without a full
serialization round-trip comparison. Prior receipt output is not compared to
a regenerated previous receipt as an unchanged-content certificate. Actual
selected-check frontier, receipt identity/order, termination/result, candidate
Git references, source state and CAS still govern progression. Unknown native
effects remain non-replayable. Current Git preconditions before real effects
remain distinct from diagnostic content certificates.

v1 reads and optional outcome shape plus actual malformed/undeclared fields.

Its missing/incompatible-check and unstaged-candidate cases still reject.

## R3 — Resolve the saved assignment and consume its original meaning

Assigned WorkOrder recovery resolves its real instance/run/Continuation, source
revision, selected Plan target, Step/generation, candidate/check references,
Required SPI and executable completion route. It consumes the selected original
input, review context, presentation and execution requirement, rather than
comparing the complete WorkOrder or Plan with a fresh projection. Diagnostic
workspace/evidence revisions, summaries and review policy metadata are not an
unchanged-content certificate. Missing independent-review requirements, foreign
assignment/target, incompatible contracts and current candidate conflicts still
fail. Actual effect scope remains owned by the retained controller and native
predecessors, not by a worker's supplied semantic body.

Work/Result v1 readers admit declared nested structure and actual typed values,
without encoding the decoded payload again as a full-body proof. Older allowed
optional-null/absent representations remain readable without rewriting rows or
granting authority. Undeclared execution/authority fields still reject.

Completion computes its semantic successor once in the owning adapter. The
response uses the committed InstanceRecord returned by managed completion, with
actual correlation/result reference and resulting state checks. It does not
reload the saved Result to prove its complete body unchanged. Response target
correlation is not semantic judgment admission or independent-review evidence.
Generic shared Result admission and completion still have connected duplicate/
body controls to remove; this does not claim their complete correction.

## R5 — Native Step commit facts, not a complete closure-policy witness

Native Step closure v2 output removes the complete policy snapshot. Its v1
reader ignores the obsolete field regardless of its former representation,
without rewriting rows, renewing authority or comparing policy identity/revision.
Declared target/commit shape and typed facts are decoded directly; optional
missing commit is an unresolved intent, not a failure of canonical-body proof.

Recovery resolves the actual Step/Plan/source/candidate/review target and selected
commit program, authority reference and committed native result. It no longer
compares a complete result payload minus its commit with the complete intent
payload. Actual selected intent/result slots, adjacent native state and Git
parent/tree/controller transition remain. Current executable incompatibility
still refuses; policy metadata or an unselected extra program does not. An
intent without its recorded commit never replays Git. No missing/withdrawn
current authority is synthesized for a new commit.

## R6 — Retain the selected parent-child invocation, not a regenerated command

The owning Phase stores a typed child Start using the existing public v1 command
wire shape. Recovery consumes this selected original command and parent input;
it does not build a fresh child command or demand whole-command/Plan/authority
input equality. A new installation's selection for new invocations is not a
certificate for the retained invocation. The original selection still resolves
through the actual installed child Operation and selection port. Actual parent
instance/source frontier, selected Plan reference, candidate/native commit chain,
review-result reference, child invocation, participant and repository/tracking/
endpoint/effect scope remain required. These references resolve real targets;
they do not certify that declarations or their presentation remain unchanged.
Repository policy-version metadata is not part of this host-scope comparison;
other consumers of the mandatory legacy marker remain unfinished.

Parent intent/result and whole-Phase Terminal readers accept declared old optional
Plan forms directly, without re-encoding a complete body for comparison. The
nested child command/result readers own their typed admission once. Unknown
nested executable/authority fields and malformed actual data still refuse.
Terminal consumes the saved parent meaning, not fresh authority presentation.
No legacy row rewrite, new authority or synthetic child completion is implied.

Parent and child completion use the authoritative native append's readback rather
than loading again to prove its unchanged body. Convergence resolves the actual
selected accepted frontier and Git target, not copied previous history, whole
observation or validation-policy diagnostic bodies. The final local observation
is not repeated solely for equality with the first observation. Actual local/
tracking/remote tips, native index/tree/parents/ancestor, clean state and current
effect authority remain checked. These separate Git observations are not atomic;
unknown effects are not replayed and no extra snapshot guarantee is claimed.

E14: GoalPhaseNativeRunSpec physically reopens prepared/executed/recorded/completed
