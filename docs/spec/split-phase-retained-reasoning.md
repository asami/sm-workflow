# Retained first-frontier reasoning

## R1 — native origin and complete cached frontier

Given a genuine first mechanical checkpoint or genuine public partition
completion whose saved outcome requires reasoning classification, When the
owning advance observes that native origin after physical SQLite reopen and
restores the calculation, Then all candidate documents, short-child assessment,
duration scores/leaders and objective need equal the complete original snapshot.
The original authority, closure and known demand are preserved, only unknown
items enter semantic preparation, and newly absorbed mechanical stages are empty.
Allocation/reply-allocation policy removal does not prevent restoration; no new
native history, row, candidate computation or semantic work is published.

## R2 — no passive execution grant

Given absent native observations or a real checkpoint with another disposition,
When reasoning restoration is requested, Then it refuses. A passive checkpoint,
snapshot, Origin descriptor or decoded receipt cannot construct the private
Source/retained calculation. A later native suspension stays an observation, not
proof that a reasoning WorkOrder was issued.

The corresponding R1/R2 examples belong to the managed-checkpoint specification.

## R3 — actual postimage and pure native issue projection

The native-bound source retains its actual calculation publication postimage,
not a history prefix reconstructed from latest current. Mechanical observation
preserves the canonical receipt.next; partition/scope/Human origins select their
independently observed whole record.next. An observed later native prefix does
not move that publication postimage or authorize another append there.

Pure reasoning issue projection copies the saved complete reasoning need and
selects its stable continuation from native instance/publication revision. The
request carries the exact assigned result; it preserves the original Start
handle/requirement and generated reasoning operation/completion contracts.
The projected suspension has exactly the actual postimage as predecessor and
the complete next revision; wire encoding retains the entire typed request.
Projection performs no allocation or fresh candidate/objective calculation and
does not publish a suspension, issue a task or grant mutation authority.

The E1/R1,R3,R4 first-root examples exercise this projection after physical reopen
without either allocation policy. After a separate later native append, they
also attempt the old suspension through the canonical managed executor and
require refusal with no issued WorkOrder and unchanged later instance. This is
negative stale-predecessor coverage, not a successful installed issuer.
Actual managed issue, retained task recovery,
completion/successor and public/default installation remain mandatory separate
runtime evidence, not established by the pure intent or its private Plan.

## R4 — actual owning-call issue and retained recovery

Given a genuine selected native reasoning source, When the internal issuer runs
under the actual authenticated original advance call, Then it independently
reobserves that source using its genuine mechanical, partition, scope or Human
reader. Full saved provenance and publication postimage must agree. Current is
read from native storage, not taken as authority from the old selected witness.
The port retains metadata only; it borrows the actual canonical Subsystem
storage/common pool and restores call binding on return, including failures.

Existing complete typed issued work is observed first. Only exact issue absence
at the exact Active unsuspended calculation postimage permits an atomic native
suspension/continuation/WorkOrder publication. Exact original work at the exact
reasoning suspension is returned unchanged; later state without work, foreign
task, different source/current or wrong owning Operation/participant refuses.
No allocation policy, fresh candidate/objective calculation or source-current
copy is an alternative route. Expired managed calls grant no retained access.

After actual commit, independent complete native instance and issued-work
readback precedes response. An unavailable commit/readback acknowledgment is
indeterminate, not success or permission for immediate retry. A later owning
call, including physical SQLite reopen without allocation policies, returns the
saved work without another append or repeating postcommit observation.

E1 has both native first roots and distinct projection-only, managed-issue and
interrupted-readback branches. The projection-only branch retains its canonical
stale-suspension refusal. Managed branches independently read actual work/current,
check exact one-revision native progress, complete cached unknown closure and
reply assignment, repeat/reopen behavior, foreign owning purpose/participant and
expired-core refusal. The interruption hook runs only after an actual native
commit and cannot supply or emulate publication evidence. E2 also refuses an
absent selected source and private port construction.

These internal port examples are not public advance/CLI/default installation
proof. Successful managed issue/completion for all four origins, native staged
collision rollback, actual provided reasoning completion/successor and the full
original public/runtime/transport/cost obligations remain required separately.

This specification covers saved-calculation restoration and the internal owning
issue port, not installed public routing. Actual reasoning completion/successor,
ALL-Built scope/Human routing, standard production, transport/recovery and full
PHASE-2 acceptance remain mandatory executable evidence, not implied by these
internal examples or by their source authoring.

## R5 — requested result and deterministic successor preparation

Given genuine native-bound reasoning source data, its actual saved WorkOrder and
current suspension, When the participant returns the assigned requested result,
Then Workflow admits the common result envelope, assigned reply and execution
evidence, classifies only the requested unknown items, and derives fresh planning
and demand versions itself. Known classifications, authority and the cached
candidate/projection/duration frontier are preserved. It continues only the
objective calculation and projects its full downstream state without invoking
candidate or reply allocation, enumeration or document projection again.

DecisionNeeded prepares no partial classifications or planning successor and
does not invent a Terminal. Crossed reply/evidence, missing classifications and
attempts to rewrite known work refuse. Completion preparation changes no native
history: the projected next record and closing value are data, not a receipt.
Recovery requires the actual adjacent completed native prefix and retained
result; a still-suspended native record with a constructed completion record is
refused. No public reasoning task is exposed as answerable by this preparation.

E1's managed branches exercise both first roots and actual retained/reopened
issued work without allocation policies. They prepare Enriched and DecisionNeeded
successors and reject crossed/partial/known-item results and fabricated completed
history, while asserting native state remains the actual suspension throughout.
Successful managed completion, staged successor/readback, all four-origin public
routing and installed Preview/Apply remain part of the connected delivery batch,
not acceptance implied by these data-boundary assertions.

## R6 — actual provided result and atomic durable successor

Given a native issued reasoning WorkOrder and its current suspension, When the
original authenticated participant returns its assigned Judgment through
`SplitPhaseService.submitReasoningResult`, Then the real result Operation reads
the original source under that same Core. It does not fabricate an advance
request, select a caller-controlled source, or gain advance's publication rights.
The native pre-issue history selects the mechanical, partition, scope-planning
or Human-resolution reader; a reader error never falls back to another origin.

Workflow admits unknown-only semantics and derives the successor versions.
Native result/closing state and one complete successor row commit together in
the Subsystem's canonical managed UoW/common pool. Enriched saves the full cached
planning successor; DecisionNeeded saves an explicit absent downstream, not a
partial plan or Terminal. Acknowledgment requires actual native/result/row
readback. An identical later reply observes the saved answer without another
write or AI call; a changed reply refuses. SQLite physical reopen requires no
allocation policy or previous conversation.

E1's managed branches exercise both original first roots, launcher and owning
Operation submission, repeated answer/changed answer, physical completion reopen
and both semantic decisions. A conflicting preexisting successor row rolls back
native completion without overwriting that row. Harmless JSON presentation
changes remain admissible through semantic readback rather than byte proofs.
An authenticated foreign participant cannot replay even an identical answer.
These examples do not yet prove all-origin public
advance routing, selected Preview/Apply, normal
default installation or complete practical three-workflow acceptance.

E1 additionally requires generated public advance to issue the first-root
reasoning task from genuine native lineage, not client-selected dispatch. While
that suspension is pending, its declared reasoning completion contract routes
ahead of older scope/partition stages. Normal owning Operation and launcher,
including physical reopen without allocators, return exactly the saved task
without another append. A prior interrupted issue is observed, not reissued.
Preview continuation is specified separately below; APPLY is not implied.

## R7 — selected Preview and observable recovery

Given a genuinely completed Enriched reasoning result and its complete saved
selected successor, When public advance runs without allocation policies,
Then it projects that selected plan, not the older reasoning frontier or a new
candidate computation. The useful PREVIEW contains the selected cut positions,
ordered work items, closure criteria, per-child duration and repository,
ownership, handoffs and validation responsibilities. No Phase document is written
and no APPLY authority is granted.

The canonical native mechanical receipt saves the selected snapshot and Active
`entry.Previewed` preparation. A separate guarded native append completes that
preparation. These are two durable steps, not an atomic two-write claim. A later
call observes actual receipt/current state and either finishes the exact saved
preparation or returns its actual Completed Terminal. It cannot replay the
calculation, create another task or append another final record. An interrupted
final acknowledgement is indeterminate; physical reopen observes completion
without rerunning the callback. Missing or contradictory saved provenance refuses.

E1's existing managed/public issue leaves exercise both first roots, owning and
launcher preview, final acknowledgement interruption, physical terminal reopen
and foreign-participant refusal. DecisionNeeded has no selected downstream and
must refuse an absent genuine Human handler in an assembly without that binding,
without a partial Preview or new native history. The connected three-workflow
assembly supplies the separate reasoning Human handler specified in R8.
These added assertions require execution; authoring alone is not
validation. All-origin continuation, APPLY, normal production assembly and the
other two usable Workflow routes remain mandatory integrated evidence.

## R8 — genuine reasoning Human successor and independent answer

Given a canonical completed AI DecisionNeeded with no partial classification or
downstream plan, When connected public advance observes it, Then the separate
`reasoning-human-direction-capability` issues a Decision whose input type is
`SplitPhaseReasoningHumanDirectionRequest`. It carries the full original unknown
WorkOrder, saved AI result and complete planning frontier, preserving authority,
known classifications and candidate order. Pending advance and another JVM
return that exact saved Decision without another AI call or native append.

When the original participant submits the Decision's common answer through the
unchanged `submitSplitHumanDirection`, Then fresh completion independently
verifies the whole issued question/result against the actual owning call and
clock. Missing or crossed evidence refuses without a write. Scope questions
retain their original type and contract; nominal routing cannot replace saved
question and original native-source verification.

ProvideResolution selects separately stored
`sm-workflow.split-human-reasoning-resolution.v1` interpretation data, naming
this Decision and the original saved AI result. Workflow requires exact ordered
unknown-item coverage, original context, rationale and answer-bound evidence,
preserves every known item, and calculates planning/demand versions and packing.
Incomplete, crossed-item/context/evidence/Decision/result data refuses before
completion. The original AI DecisionNeeded is never rewritten as Enriched.

Canonical Human answer, adjacent native state and full selected successor commit
in one managed UoW/common pool. Defer/Cancel instead commit the stopped result
and reach the existing typed BLOCKED/CANCELLED Terminal. An identical reply is
observation; a changed reply refuses. Another JVM after completion uses advance
to restore the selected whole-frontier Preview or stopped Terminal without
resubmission, reissuing AI, or document effects. Terminal observation preserves
the exact response/history. Uncertain readback remains indeterminate, never an
automatic retry. Connected direct Operation examples are not Phase6 CLI/skill
integration or whole-Phase acceptance.
