The new CML Required Operation `MergeReviewService.reviewNativePendingMerge`
receives the selected instance/native validation revision, original ordered
parent OIDs, actual index tree, bounded complete parent-relative diffs/changed
paths, selected validation policy and actual checks. These are semantic review
inputs, not management certificates. Workflow obtains them through canonical
fixed-target Git ProcessExec; no AI path/argv/receipt can choose the repository.
Binary/oversized/incomplete or unsupported captures fail explicitly.

`RepositorySyncService.submitNativeMergeReview` is the provided paired result
operation assigned in that WorkOrder. Clients return its ContinuationResult;
they do not decide which workflow stage or effect to execute. The result contains
only accept/repair/decision-needed/reject, rationale and bounded findings on
issued paths. The host verifies actual independently admitted reviewer evidence;
an AI workerIdentity string or acceptance claim is insufficient. There is no default
permissive verifier. Only genuine native issued work/current suspension/original
Start and actual committed completion can select the corresponding successor.

Issue/suspension and result/closing append use canonical shared Subsystem storage.
Pending and completed reopen reuses actual native work/completion without another
review allocation or command replay. Accepted review stays before authorized
commit/push/final convergence. Repair/DecisionNeeded/Reject stay nonterminal until
their separately connected handling; none is a Human answer or implied consent.
