# AI使用量の計測・集計・完了表示

Status: accepted target specification; implementation planned in Phase 13.
Date: 2026-10-22

## U1 対象と責務

sm-goal-phase、sm-repository-sync、sm-split-phaseの呼び出し終了時に、今回の
呼び出しに帰属する親処理とsubagent（再委譲を含む）の消費トークン数を表示する。
併せて実際に使用したモデルの種類とモデル別の思考回数を表示し、親チャット分と
subagent分を分ける。親チャット自身の計画・判断・継続・結果作成も対象範囲内なら含める。
表示の最上位区分はCodexとローカルLLMに分け、各区分内で親/委譲先・モデル別の
トークン数と思考回数を示す。両者を混ぜた合計だけの表示にはしない。
完了、中断、失敗、ユーザーへの制御返却で表示できる共通の結果投影とする。
制御返却はWorkflow全体の完了を意味しない。今回の呼び出しと再開を含むSession累計を
混ぜず、最初の提供範囲は「今回の呼び出し」とする。

計測・集計・保存・表示はhost/runtimeが機械的に行う。AIの自己申告、回答文字数からの
推定、記録だけのAI呼び出し、使用量取得のための反復AIポーリングを使用しない。
既存の[実行結果記録](native-host-execution.md)とCNCF WorkflowExecutionHarnessの
Resourcesを再利用する。入力・出力以外の共通型の拡張が必要ならCNCFをproducerとし、
sm-workflowや各スキルに競合するprovider固有の計測モデルを作らない。

## U2 計測範囲と帰属

hostは開始時に呼び出しの識別と、実際のSession/Run/Action/Step、provider実行、
thread/turn/attemptおよび委譲関係を必要な範囲で関連付ける。既存の識別を再利用し、
新たな業務承認台帳や計測用Workflowを作らない。途中から採用する場合は開始位置を記録し、
過去の未計測部分まで取得済みとしない。

- 対象呼び出しの親、子、孫の実行を含める。失敗した試行と実際の再試行も各々含める。
- 無関係なチャット、同じアカウントの別プロジェクト、別呼び出しは除外する。
- アカウント累計の開始・終了差分を呼び出し使用量の代用にしない。
- 同一turnを複数のスキル呼び出しが共有する場合、帰属できる計測境界がなければ
  全量を各呼び出しへ計上しない。未分離の範囲として明示し、部分計測とする。
- 複数モデルの実行は実際のモデル別観測を保持する。不明なモデルを推定しない。

### U2.1 CodexとローカルLLMの区分

実際の推論先に基づき、互いに重ならない表示区分を決める。クライアント/呼び出し元と
推論先は別に保持する。CodexがローカルLLMを呼ぶ場合、そのモデル消費はローカルLLMへ
一度だけ計上し、Codexクライアント経由という理由で両方に入れない。

| 表示区分 | 対象 |
| --- | --- |
| Codex | Codexのサービス側モデル実行として観測された消費 |
| ローカルLLM | hostがローカル推論先として確認したモデル実行の消費。Codex経由も含む |
| その他provider | 上記以外と判明している実行。実際のprovider名を併記 |
| 実行先未確認 | 実行は判明しているが推論先を分類できない範囲 |

モデル名、親/子の役割、CLIがこのマシンで動くこと、localhostのproxyだけでローカルと
推定しない。hostの実際の接続先とadapter観測で区分する。途中の切替/再試行は各実行先へ
帰属させる。tokenが取得できない場合も判明した区分・モデル・回数は保持する。

区分ごとに入力/出力、取得可能な内訳、思考回数、親/委譲先とモデル別内訳、計測状態を
独立して表示する。区分をまたぐ親の包括集計を分離できない場合は「区分別内訳未取得」と
し、既知の子の値を二重加算しない。観測済みの非重複分だけを各区分へ入れる。
未使用と確認できた区分は「未使用」、使用したがusageがない場合は「未取得」とする。

全体token合計を補助的に出す場合も区分別表示を残し、provider報告値の単純合計である
ことを明示する。異なるモデルのtokenを共通の計算量・料金単位として扱ったり、
Codex利用枠とローカルLLM消費を換算したりしない。全体合計から料金削減額を推定しない。

## U3 観測値と二重計上

各観測は元実行の識別、対象範囲、観測元、観測位置/版、確定状態を保持する。
adapterは実際のusageが自己分だけか子孫込みか、単一区間か累積値かを宣言し、
実測とproducer契約で確かめる。Codexの親usageに子が含まれるとは仮定しない。

| 観測の意味 | 集計 |
| --- | --- |
| 相互に重ならない自己分の実行値 | 親＋各子孫を一度ずつ加算 |
| 子孫込みの親集計 | 親が含む範囲を採用し、その子孫値を重ねて加算しない |
| 同じ実行・範囲の再送/再読 | 同じ観測として扱い、加算しない |
| 同じ実行の累積更新 | 確認できた新しい値へ更新。通知ごとの累積値を足さない |
| 重複範囲、巻き戻り、境界不明 | 確定できる非重複部分だけを表示し、残りは未取得/未確定 |

再接続・再開では保持した観測位置を使う。累積差分は同じカウンタと開始・終了範囲を
確かめられる場合だけ使用し、負の差分をゼロにして成功扱いしない。
同一実行の包含関係が不明なら、親と子を盲目的に合算しない。
この重複処理は計測観測だけのもので、業務操作の再実行/承認/修正回数を変更しない。

標準表示は入力・出力tokensとする。キャッシュ入力・推論出力が取得できる場合は
内訳として保持する。adapterが確認した包含関係に従い正規化し、内訳を親項目へ
再加算しない。入力＋出力の合計は同じ対象範囲の両値が揃う場合に限る。
残りコンテキスト量、利用枠の消費率、トークン数、課金額は別の量であり換算しない。
金額推定、価格表管理、LLMの能力評価は本仕様の初回提供範囲外。

### U3.1 使用モデルと「思考回数」

「思考回数」の単位は、実行基盤が観測した個々のモデル呼び出し1件とする。
AI内部の思考段階やreasoning文章の数は数えず、内部思考本文の取得も要求しない。
一つのチャットturn内でツール利用後にモデルが複数回呼ばれた場合、識別できる各呼び出しを
それぞれ数える。ツール実行、usage通知、Advance、agent起動そのものは思考1回ではない。
実際にモデル実行が始まった失敗・キャンセル・再試行も数える。実行前拒否は確認できる場合
のみ0回とし、開始自体が不明なら未取得/未確定とする。

集計軸は「今回の呼び出し × 実行先区分 × 親/委譲先 × 実際のprovider/model × 観測できたreasoning effort」。
親は今回のスキル呼び出しを担う元チャットで、子の親になったsubagentは委譲先のままとする。
詳細ではexecutor/threadと親子関係・深さを保持し、親と同じモデルを使ったsubagentも
親チャット分へ混ぜない。総回数は同じ単位の親自己分＋委譲先自己分の非重複合計とする。

実際に解決されたモデル識別を優先し、要求モデル/設定値/表示aliasと区別する。
実行途中のモデル変更・rerouteが観測できた場合は実際の実行先ごとに記録する。
reasoning effortも観測できた実適用値のみを内訳に使う。設定値しかない場合は
「設定値・実適用未確認」と表示し、トークン数や時間からhigh等を推測しない。
モデル数は確認済みの実モデル識別の種類数とし、同じ実モデルのaliasやeffort違いを
別モデルへ増やさない。実モデル不明分は「モデル未取得」へ分け、回数が判明していれば保持する。
analysis/design/review等の業務上の思考種別はモデル名やreasoning effortとは別軸である。

同一モデル呼び出しの開始/完了/usage更新/再送を重複カウントしない。必要な識別は
既存provider request/attempt等を使用する。親が子孫込みの回数を返す場合もU3の包含規則に
従う。モデル呼び出し数が公開されずturn数だけ判明する接続では「ターン数」と別表示し、
思考回数へ換算しない。subagent1件や1turnを一律1回と扱わず、token合計からも推定しない。

## U4 未取得と計測状態

値の未取得はNone/unknownとし、0は実際に0と観測された場合だけ使用する。
計測状態とWorkflowの成功/失敗は独立させる。

| 表示状態 | 意味 |
| --- | --- |
| 全対象取得済み | 対象の委譲関係と完了境界が判明し、当該指標が全範囲で重複なく確定 |
| 部分計測 | 一部だけ確定。表示数値の範囲と未取得/未確定の理由を併記 |
| 未取得 | 今回の呼び出しへ帰属できる使用量が取得できていない |

親だけ/子だけ取得、子孫の存在数が不明、処理継続中、通知欠落、provider非対応、
同一turn内の帰属不能、保存失敗等を区別する。判明した件数だけを示し、不明な子孫数を
作らない。部分計測を「全消費量」と表示しない。
失敗やキャンセルでも観測できた消費は残し、usageがない失敗を無料と扱わない。
計測状態は実行先区分ごと、かつトークン、思考回数、モデル識別・親/委譲先内訳ごとに保持する。
例えば「トークン：全対象取得済み／思考回数：未取得／ターン数：取得済み」と表示できる。
全体を「全対象取得済み」とするのは必要な各指標が揃った場合に限り、ある指標の取得成功で
他の未取得を隠さない。reasoning effort未確認も明示し、モデル/回数の既知部分は失わない。

## U5 完了表示と確定タイミング

既存の結果表示へ短い共通サマリーを付ける。例（架空の数値）:

```text
sm-goal-phase：Step完了
AI使用量（今回、親＋委譲先、失敗・再試行を含む）
Codex：入力 120,000 / 出力 8,000 tokens
  入力のうちキャッシュ：100,000 tokens
  計測状態：全対象取得済み
ローカルLLM：入力 40,000 / 出力 3,000 tokens
  計測状態：全対象取得済み
```

モデル・思考回数の表示例（架空のモデル名と回数）:

```text
Codex：使用モデル1種類 / 思考9回
  親チャット：モデルA / high    6回
  委譲先：    モデルA / high    3回
ローカルLLM：使用モデル1種類 / 思考9回
  委譲先：    モデルB / medium  9回
思考回数：合計18回（モデル呼び出し数）
```

同じモデルでも親/委譲先の行を分ける。内訳と合計には同じ計測範囲・単位を使用する。
思考回数が取得できない場合は「思考回数：未取得（取得可能な指標：ターン数…）」等と表示する。
これはモデルの性能比較ではなく、実際の使用内訳である。

部分計測例は「取得済み分：入力 … / 出力 …」「委譲先1件未取得」のようにする。
子数が不明なら「委譲先の全範囲未確認」とする。詳細の実行別内訳は参照で取得できるようにし、
毎回全履歴をAIへ渡さない。

最後のAI回答自身の消費は、その生成終了後にhostが受け取るusageで確定する。
hostが表示できる場合は完了通知後に追加表示する。スキルの回答本文にしか表示できない
接続では「回答生成前まで」と明示して部分計測にし、後続通知で保存値を更新する。
表示だけの追加AIターンを発生させない。子が継続中、usageが遅延/欠落している場合も
通常の制御返却を妨げず、その時点の部分計測を表示する。
遅れて届く観測は同じ呼び出しの集計を更新し、業務結果を再実行しない。

## U6 保存と既存運用

元の実行観測を正本にし、既存host Sessionと共通ExecutionObservationの責務に沿って保存する。
共通Journalは要約・計測状態・元結果への参照を持ち、必要な機械的証跡は
[Common Evidence](common-evidence.md)を使用する。Gitへのrawログ保存、全sessionログの走査、
会話本文や認証情報の収集は必要としない。汎用イベントストアを別途新設しない。

取得/保存/表示の失敗は診断と未確定状態を残すが、業務成功を失敗へ変えず、追加承認、
再レビュー、テスト再実行、別Workflow開始、同じAI作業の再実行を要求しない。
既存Goal、Session、Plan、履歴、修正回数、検証結果を維持する。対象に存在しない実測を
過去の記録へ捏造して補完しない。

## Codex接続候補と確認範囲

[用語規約](runtime-caller-terminology.md)を適用する。以下を含む旧記述のhost/adapterは
実観測の取得と返却ならCallerIntegration、実行機構ならRuntimeとして整理し、
hostを非ネットワーク概念の新しいAPI/設定名に使わない。具体名の変更は同規約の
対応表と採用計画に従い、過去の観測を新しい実行結果として書き換えない。

2026-10-23追記：Codex固有の情報取得は既存のCodex呼出元へ要求を返す方式とする。
sm-workflow/CNCFが`host_source_read`や`process_exec_text`で取得プログラムを
起動する方式は採用しない。呼出元が既に観測したusageや利用可能な取得手段から
結果を返し、同じ呼び出し/Sessionへ関連付ける。利用可能な通知が既に届いていれば
追加要求を作らず再利用する。情報取得だけのために別のAI実行を開始しない。
取得できない情報はcoverage/未取得に反映し、通常の開発を止めない。
以下は既存接続で利用可能な観測源の候補であり、新規Codex実行を起動する指示ではない。

公式の[App Server](https://learn.chatgpt.com/docs/app-server)には
`thread/tokenUsage/updated`通知とアカウント全体の`account/usage/read`がある。
[非対話CLI](https://learn.chatgpt.com/docs/non-interactive-mode)は
`codex exec --json`の`turn.completed.usage`を返す。
前者のスレッド通知または後者を、実際のhostが所有する実行接続に応じて採用する。
APIの存在だけでは現在のスキル/チャットから取得可能とはしない。
親子包含、累積値の意味、回答終了時の通知順、失敗時の取得範囲は実際の接続で確認する。
モデル呼び出し数・実モデル・reasoning effortが同じAPIから得られるとは仮定しない。
使用量通知とは別に実行基盤が提供する識別/通知を確認し、公開されない指標は未取得とする。
アカウント全体のusageやrateLimitsを呼び出し集計へ流用しない。
