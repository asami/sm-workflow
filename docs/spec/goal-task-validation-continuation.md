# GoalTask supplemental validation continuation

An active non-delegated code GoalTask can have a complete successful historical validation batch that no longer satisfies the current admission contract. The task's original input, implementation result, candidate, counters, source and successful typed receipts remain unchanged. A successful full Test retains its actual Test kind and does not substitute for TestOnly.

The public `describeGoalTaskValidationContinuation --sessionId` describes an exact eligible Assess frontier. Only a complete successful prefix with missing required Compile, nonempty TestOnly or required FixCheck qualifies. The derived missing typed checks have unique identities and consecutive ordinals following the original selection. Pending, uncertain, partial or unsuccessful original checks do not qualify.

`adoptGoalTaskValidationContinuation` takes exactly one structured `input` or `inputResource` containing that exact target, session, actual participant, independent Human reference, rationale and either `AuthorizeMissingChecks` or `Defer`. Prepare and provision independent Human evidence for `GoalTask` / `validation-continuation` through the normal evidence owner. Defer writes nothing. Authorization checks the retained frontier and candidate freshness and appends a native checkpoint only; neither operation launches SBT, stages, commits or issues repair work. Identical adoption collects the existing direction.

A separate ordinary Advance admits each supplemental typed operation through the existing CNCF SBT/UoW owner. Host bindings are not admitted by description or adoption. A missing binding becomes the normal confirmed nonexecution/AdmissionBlocked state; the owner corrects host configuration before continuing. Successful prefix receipts are never rerun merely to satisfy the new contract. Assessment still requires the exact complete successful batch, Compile, nonempty TestOnly and required FixCheck before normal review and commit.

For the historical `fix-check`, `test` ordering, register the normal typed host workspaces `sm-workflow-repository-validation-3` for Compile and `sm-workflow-repository-validation-4` for TestOnly with an appropriate nonempty fixed suite selection. The caller must use the original active Session and its actual public description; do not restart, re-submit, rewrite retained state or fabricate evidence. The selected suites and host grants remain the host owner's responsibility.

Owner procedure after selecting the correct installed component and host:

1. Register the missing fixed typed host bindings at the ordinals in the description, including the focused suite selection, and preserve the existing Task workspace, original evidence and Session.
2. Call `GoalTaskService.describeGoalTaskValidationContinuation --sessionId <original-session>` and retain its complete response. The `target` and `choices` come from this response; do not reconstruct them.
3. Record the actual Human's choice, rationale, participant and artifact reference in a complete `GoalTaskValidationContinuationInput`, using the unchanged target and original session ID. For independent evidence, invoke `NativeWorkflowPreparationService.prepareEvidence` with family `GoalTask`, kind `validation-continuation`, the description and answer file URIs, the same reference, actual execution evidence, issuer, time, collection and participant. The independently observing host provisions the prepared row; preparation alone is not authority.
4. Call `GoalTaskService.adoptGoalTaskValidationContinuation` with that complete input, inline or via `inputResource`. Confirm `resumed-awaiting-advance`; a repeated identical call collects `already-resumed`. `Defer` leaves the frontier unchanged.
5. Separately call ordinary `GoalTaskService.advanceGoalTask` for the original Session. It runs only the selected missing suffix under the existing typed CNCF executor. If binding admission reports confirmed nonexecution, correct the normal host declaration and use the existing ordinary continuation; an uncertain effect requires observation and is not replay authority. Then follow the actual native review and commit result.

The preparation and answer artifacts in this procedure must reflect real independently observed Human direction; the disposable installed fixture's specification-owned evidence is not a real consumer's consent.
