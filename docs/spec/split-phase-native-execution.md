## R1 — Semantic kind and independent obligation

Split's public thinking modes remain partition **design**, scope **design** and
reasoning **analysis**. Internal `Classification.semanticRequirementC` derives the
existing deterministic reasoning level/class while preserving every other member
of the original requirement, including `reviewRequired`, capabilities, risk and
disposition. DESIGN and ANALYSIS can inherit an independent-review obligation.
That obligation must never be cleared to obtain INLINE placement. The strict
Goal/Repository `requirementC` review-kind equality guard and failure remain
unchanged; the internal Split helper is no universal relaxation.

## R2 — Explicit finite Component input

Optional `sm-workflow.execution.split-work` accepts a structured ConfigurationValue
or JSON string with this exact consumed schema:

```json
{
  "schemaVersion": "sm-workflow.split-execution-work.v1",
  "partition": {"kind": "DESIGN", "complexity": "STANDARD", "domain": "PROGRAMMING", "footprint": "SMALL"},
  "scope": {"kind": "DESIGN", "complexity": "STANDARD", "domain": "PROGRAMMING", "footprint": "SMALL"},
  "reasoning": {"kind": "ANALYSIS", "complexity": "STANDARD", "domain": "PROGRAMMING", "footprint": "SMALL"}
}
```

All three members are explicit, with the shown semantic kinds. Complexity is
TRIVIAL/SIMPLE/STANDARD/COMPLEX, domain PROGRAMMING/ENGINEERING and footprint
SMALL/MEDIUM/LARGE, decoded by the shared classifier. Nonreview complexity derives
Routine/Standard/Deep exactly as before; domain and footprint confer no concrete
selection authority. Missing/null consumed fields, unsupported enums, wrong kind,
wrong schema and null typed Options/members fail at their owner. Unused diagnostics
and model/provider hints are inert. Absence stays absent; no default classes exist.

## R3 — Fresh canonical execution binding

The normal Split Declaration appends defaulted optional classifications and the
existing canonical `workflow.execution.profiles` / `sm-workflow.execution.origin`
pair, preserving old three-argument construction. Ordinary persistence binding
validates input and pair shape before binding storage. Host composition resolves
the same keys; it does not require mappings for unused workflow families.

Binding requires an actual fresh WorkOrder with a valid base requirement and no
preexisting disposition. Explicit finite work selects its semantic derivation,
then the existing Goal adapter and CNCF own concrete profile, placement and
independence. Mapped fresh work requires explicit Split classifications and its
class in the mapping. Missing input/class fails without fallback. Logical-only
classification is allowed; all-absent retains original work. Selected work cannot
be rebound or cleared, even after configuration disappears; Wait is not work.
There is no product provider/model/effort ranking or profile-name policy.
CNCF same-profile optional work may be INLINE/OPTIONAL; inherited
`reviewRequired=true` remains DELEGATED/REQUIRED. Isolation preference stays CNCF's.
Configuration supplies no observation, capability, review or effect permission.

## R4 — Partition first-issue ownership

After actor admission, the owning call borrows its canonical storage and loads
`binding.context.record.owner.continuation` before allocation or issue preparation.
An actual saved interaction returns unchanged. Only absence decodes allocation,
allocates, calls pure preparation, binds Partition and suspends that exact selected
interaction under the original intent in the same ExecutionContext/storage scope.
Redisplay creates no identity, revision or allocation and invokes no mapper.

## R5 — Scope and reasoning first-issue ownership

Scope retains pure preparation, actual load, saved Pending and completed-source
branches. Only the missing-issued-row branch binds Scope immediately before native
suspension and returns the selected Pending work. Reasoning retains pure
preparation, identity and actual native load; only absence binds Reasoning before
suspension and the original post-suspension observation. All pure constructors
remain shared with semantic completion and never invoke classification or mapping.
No completion rewrite, migration or reclassification of saved work is permitted.

## R6 — Retained Session and genuine semantic completion

The host prepares and retains `NativeWorkflowHostExecution` Session from the first
actual public issued context and original canonical mapping/origin. Pending display
returns the same actual native issue; reopen restores the retained Session against
that issue using CNCF serialization, never prepares it against newer mapping.
New valid configuration can omit the original class without changing pending work.
Completed harness observations accompany the original typed semantic result and
its genuine assigned reference. Missing or crossed execution observations fail
before native progression. Existing independent completion evidence, CAS, current
actor and scope admission remain strict. Submit acknowledges only that result;
a separate Advance selects the next work or the complete original Preview.
Human directions retain their original independently provisioned consent protocol.
No persisted business schema, public Operation, CML/generated ABI, provider engine,
bootstrap, pool or runtime driver is added.
