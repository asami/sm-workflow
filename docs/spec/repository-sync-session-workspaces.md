# RepositorySync Session candidate workspaces

The Session owns each selected purpose candidate and its validation connection.
Ordinary project validation supplies the checks; the host supplies an admitted
source, candidate-parent and alias policy and their actual permissions. The
caller supplies targets and semantic grouping, not a per-Session slot recipe.
Existing explicit fixed slots remain supported.

The candidate allocation and Git materialization are separate effects. Each
has its own native intent and result; a resultless intent remains unknown and
is not replayed. The allocation retains logical identities only. Materialization
retains its actual typed Git facts, followed by actual Root and Head observations.
The existing CNCF workspace owner reacquires the scoped candidate against those
facts before checks and review. A missing host policy is reported before an
allocation intent, with the prepared candidate and Session preserved; changing
that external prerequisite permits normal continuation in the same Session.
No configuration property supplies a filesystem or process grant.

Ordinary discovery builds and selected test batches retain separate intents and
observations. Earlier accepted grouping, candidates, results, failure history
and repair accounting are not replaced by a setup wait. A failed or unknown
effect remains with its existing owning disposition. These source changes and
the bounded installed fixture still require native validation and review before
they establish delivery evidence; they do not complete the broader Phase 8.
