Phase 5 implementation-drift correction under its adopted removal policy.
Source and executable examples are **UNVERIFIED**. This is not a new policy,
approval, repair frame or acceptance closure.

## R1 — Human consents to an invocation, not unchanged copied infrastructure

The producer selects actual component instance, original Start address,
allocated Workflow instance/executable reference and command: selected invocation,
participant, idempotency key, source Phase, PREVIEW/APPLY mode, source authority,
optional snapshot, origin and proposal selection. Source snapshot/authority and
selected proposal references resolve the actual consent target. They are not
identity/revision substitutes for proving unchanged declarations or bodies.

Provider configuration, complete selection record/recommendation, proposal
children, source lines and generator provenance are not copied into independent
evidence. The original Start remains the owner of its retained source/proposal
meaning; this change neither truncates that original input nor substitutes a
newly loaded proposal. Later preparation/planning consumers still need their
own connected correction; this scope change does not claim that they are fixed.

E1 compares typed production projection and original legacy scope.
E2 changes even unusable historical infrastructure/selection/proposal-child
copies and source/generator markers. Scope and original occurrence stay usable;
malformed current public Start input is not authorized by this legacy example.

## R2 — Real consent and actual-call ownership remain

The host EvidencePort receives selected scope and its lookup target, not a
complete Start. Its Reader owns issuer/purpose/actual invocation scope/participant/
occurrence admission using the current host declaration and actual call clock.
No copied receipt, issuer getter or second evidence check returns to the consumer.
The assembly no longer carries a second Start validity clock. An
authorized Human relay need not be the executing Start participant; actual
Start principal authentication still belongs to its admission boundary.

Admission owns the prepared Start for its actual call. Execution obtains that
input from admission instead of taking another candidate and comparing complete
records again. This is actual call ownership, not a replacement body seal. Native
managed storage still owns call lifetime, state, CAS, scope and permission.
No later Apply, Git/SBT/other command, review or closure grant is supplied here.

E3 rejects actual owner/instance/executable/Start/source-authority/actor/invocation/
mode substitution, crossed issuer/purpose/lookup and future occurrence.
Existing managed Start examples retain absent/foreign/indeterminate consent,
current authentication, committed-state recovery and expired-call failures.

## R3 — Storage and historical reading carry selected meaning

NativeHostEvidence v7 writes selected Start attestation alongside existing
effect/review/Goal/Repository/Split Human contracts. V1–v6 reads extract original Start
meaning from the historical typed-Start envelope without decoding unused copies,
rewriting records, renewing evidence or proving source/generator equality.
Current nested attestation is closed: required facts/types remain mandatory,
and complete copies, source/generator witnesses or added grants cannot return.
Outer storage versions, size, independent record-read authority and time remain.

E4 covers v1–v6 extraction, current v7 output, original time and closed shape.
These passive codec examples and specification-owned managed fixtures do not
prove genuinely independent Human ingress or all historical physical migrations.
