# Native independent Split Start applicability

Date: 2026-10-11. Phase 5.2 adopted removal-policy migration. Current executable
inputs are UNVERIFIED; no new approval, counter or repair frame.

## R1 — Consent to an actual invocation

Current producer emits component owner, participant and the three business inputs
(sourcePhaseIdentity, invocationMode,
optional proposalReference), plus the actual source reference/Phase/authority
and optional proposal target. No full command, saved selection, idempotency echo,
saved Workflow definition/revision, snapshot/origin witness, provider/configuration
or proposal body is encoded and reselected. E1/E2 exercise current projection and
unused fields; obsolete command/definition annotations are inert.

Start reference is the separate external allocation lookup; neither that
reference nor an allocated Workflow instance is in the current consent binding.
[Public host preparation](native-host-start-preparation.md) consumes actual
selected allocation/Source rows and the current component owner through the same
passive projection. It invents no Workflow instance and reads no private Workflow
storage. Genuine independently attributable operator consent and trusted managed
provisioning remain separate requirements.

## R2 — Actual consent boundary, not duplicate native validators

Reader owns configured issuer/purpose/lookup/actual target/non-future occurrence
and managed read permissions. A foreign invocation cannot reuse consent. Host
projection selects the actual consent targets, not stored command/body agreement
or a second mode/Workflow membership admission. Actual native Start admission resolves inputs and
owns participant, scope, state and permissions. No later Apply/Git/SBT authority
is derived from this consent. E3 checks actual foreign targets and issuers.
Unrelated framework recovery/concurrency facilities are not modified or reverified.

## R3 — Current selected storage only

NativeHostEvidence v7 is the only runtime format. No v1–v6 typed-Start extraction,
expiry normalization or exact-key gate remains. Unknown unused fields, including
commandGrant, are discarded and never authority. Missing/mistyped consumed source
data fail decode. E4 covers current round-trip/unused metadata/required input,
not a legacy-reader matrix. Historical records remain untouched; unsupported old
runs restart NEW with independently issued current records. External databases
are not inferred absent or silently rewritten.

Typed Split Start allocation/record writers and readers use their current v3
representation only. A routing read consumes Start reference, allocated instance
and participant; it does not read fresh source/proposal/input bodies or re-admit
the separately selected host selection. Old full-record-to-allocation projection
and command/definition mirrors are removed, not retained as compatibility.
Current preparation combines actual source/proposal relationships and mode; the
Human action consumes independent consent once and creates a NEW native instance.
It does not load or certify original history to recover/replay Start.

## Remaining connected work

Selected normal Operations and host suites require fresh runner validation.
Internal/storage/legacy/CML/ABI migration and connected review/release remain.
This slice is partial, not Phase acceptance or a new restoration guarantee.

The [adopted security profile](../phase/phase-6-security-review-profile.md)
selects changed input/target, consent versus authentication/effect authority,
least-authority DataStore use and explicit file/process escape evidence through
existing Step/Phase owners. Required actual provider evidence remains open until
admitted; imported plans and passive JSON establish no security PASS or provider
availability. Normal command execution and the single lightweight FQN client
Start smoke retain their current scope.
