## Request and destination

Use an existing authorized chat delivery tool. Genuine Human direction must cover
the selected existing destination, objective, repository, literal ownership,
conditions, selected operations/effects and result return unless that direction
already exists. Retain its actual source. The requester and destination remain
distinct owners. A display name alone is ambiguous when multiple chats share it;
retain the selected exact chat identity with the actual delivery observation.
Dispatch acknowledgement means dispatched; it does not mean observed work,
validation, review or completion. Do not fabricate an issued request from it.

## Public result attachment

`NativeWorkflowPreparationService.prepareTaskFixDelivery` accepts
`WorkflowTaskFixDeliveryPreparationInput`:

| Field | Value |
| --- | --- |
| route | sm-test-fix, sm-review-fix or sm-goal-task |
| requestIdentity | Exact original destination business requestIdentity |
| requesterIdentity / destinationIdentity | Distinct selected existing chat identities |
| destinationParticipant | Actual participant admitted at destination Start |
| result | Absolute local file: URI containing the unchanged public destination response |
| sourceReference | Actual returned tool/artifact identity and revision |

Pass the generated DTO as ordinary `--input` JSON to the installed operation
`org.simplemodeling.textus.SmWorkflow.NativeWorkflowPreparationService.prepareTaskFixDelivery`
with the selected runtime configuration and normal `--json` output. The adapter
reads only that declared file through the current call's Resource context. It
never reads native stores, dispatches a message or creates a workflow.
The output `WorkflowTaskFixDelivery` retains the complete original Record,
destination sessionId, selected input, candidate/diff, receipts, original finding
dispositions, review references, counts, evidence, commit and projection warning.

The derived disposition is `completed-committed` for a reviewed Task with its
matching actual commit, `accepted-uncommitted` for accepted standalone FIX,
`no-change` when the native request reports no change, `closure-failed` for failed
Task commit, and `observed-work` or `observed-wait` for unfinished work. No-change
creates no empty commit; standalone initial no-change can retain a previously
selected dirty candidate. UNKNOWN/intents remain waiting and authorize no replay.
Successful terminal projections require the existing selected check assessment;
empty or compile-only code validation cannot become successful delivery.

This is a passive projection of **caller-observed** evidence. Exact metadata and
shape checks authenticate neither the source nor Human consent, independent
review or effect authority. They cannot convert supplied JSON into a native
receipt. Retain the actual destination tool response and source provenance beside
the packet. Native workflow admission remains the authority for destination
acceptance. A source fixture is never installed acceptance evidence.

## Requester adoption

The authorized caller returns the packet and actual evidence through its existing
chat tool. The requester uses
`NativeWorkflowPreparationService.prepareTaskFixAdoption` with
`WorkflowTaskFixAdoptionPreparationInput`: absolute `delivery` file URI, exact
`requestIdentity`, `requesterIdentity`, `destinationIdentity`, explicit
`disposition` (`adopt`, `defer`, `reject`) and concrete `rationale`.
It checks the retained identities and reprojects the original response to refuse
an edited closure label. Unfinished work may be deferred/rejected, never adopted
as completed. Output `WorkflowTaskFixAdoption` is an attachment only: it creates
no datastore row, authority, acceptance, continuation or implicit Submit/Advance.

Consume that attachment as referenced context in the requester's **existing**
issued semantic work and ordinary result route. Judge applicability and required
affected integration there; destination checks prove only their actual scope.
Keep the original requester Session/Plan/continuation and its histories/counters.
Do not replay an accepted Submit, migrate an active Phase, restart a repair or
repeat successful checks merely to install or receive a result. The requester
retains its own completion obligations; an adoption attachment does not complete
its Phase. If no current native work exists, retain the attachment with the
requester's ordinary conversation outcome instead of inventing a workflow.

For separate-chat display, use the dispatch observation and existing caller
information tools/operations. Observed work means actual selected source shows
work; observed wait means its actual wait/unknown/nonterminal evidence. Tool
termination alone does not prove a descendant test or Git effect. Information
absence remains partial/unavailable. Reuse already available observations or an
explicit finite information request; no status-only AI turns or timer monitoring.

## Installation and preservation boundary

The owning runtime publishes the new candidate through its existing authorized
local publication route, then deploys the component and matching skill resources
into a separately selected installation. Publication is an actual effect with
its own result, not an instruction for these skills to run SBT. Qualify the public
preparations and three native routes on that installed artifact before claiming
availability, and retain actual publication, installation, execution and return
observations. Source archive fixtures alone prove none of these effects.

The GoalPhase closure codec retains historical native-step-closure **v3** and
supports producer-authored **v4** partial completion with the exact retained
P→C→D chain. Release continuation targets preserve optional admission and partial
completion through their closed codecs. The qualified Phase has traversed its
actual Plan2 accepted prefix and current-Step inventory continuation on the
installed consumer; this establishes that recorded compatibility scope rather
than compatibility with arbitrary histories. Runtime-owned LocalPublication is
available through its admitted existing operation and selected publication host.
Retain actual image, candidate and qualification references when adopting changed
bytes. Do not migrate stores, replay accepted work, silently copy producer repairs
or relax codec/schema gates. New Task/FIX demonstrations use separate explicitly
selected inputs and runtime observations.
