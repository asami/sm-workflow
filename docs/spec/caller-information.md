# Information returned by the existing caller

The private exact public-source selector is shared with
[validation repair adoption](goal-phase-validation-repair-adoption.md). Existing
caller-information Operations still require their genuine issuedWorkContext;
the native historical adapter never manufactures a semantic request. Selection
does not authenticate a page or associate it with an old native intent.
Historical association and unresolved effects require explicit independent
Human adoption through the distinct new contract.

The normal `NativeWorkflowPreparationService.prepareCallerInformation` Operation
returns `WorkflowCallerInformationRequest` for an actual issuedWorkContext. It
retains the original handle, Session, run, continuation, expected revision,
completion scope, information kind, exact source locator and caller identity.
It selects no executor and performs no source acquisition or workflow mutation.

The same caller uses already available observations or its ordinary public tools.
It retains the actual tool exchange and returns `WorkflowCallerInformationObservation`
through `recordCallerInformation` with the original request and current issued
context. Original public `read_thread` JSON remains opaque text so Record
normalization cannot rewrite source keys, arrays or numeric observations.

`available`, `partial` and `unavailable` are explicit. Exact thread/turn/item and
kind must match. Available execution-terminal information requires an actual
completed/failed command item, exit code and untruncated source. The returned
terminalObservation is that original tool item, not a success receipt. It proves
only the selected caller tool invocation's terminal state, not descendant or
helper-child termination, Git effects, Test success or business acceptance.
Partial/unavailable never manufacture that proof. Optional usage absence does
not block unrelated work.

Results retain the same issued context and source reference. Repeating passive
delivery returns the same facts without replaying a command or appending a
workflow direction. A crossed Session/continuation/revision/scope refuses. The
caller continues the existing issued route with its ordinary semantic result;
information return itself performs no Submit, recover, Advance, persistence,
independent review or Human admission. A stale passive observation does not
replace the owning workflow's normal current-state checks.

The public source and caller identity are attribution, not a cryptographic
authentication token or permission. Actual tool evidence remains with the
caller. Existing independent Human/effect authority must still be established
at the normal owning boundary; a returned userMessage alone grants no consent.

CLI helpers use `--runtime-root` for the selected configuration directory.
`prepare-information`/`record-information` forward the original issued work and
selected resource URIs. They never run another Codex model, source provider,
acquisition ProcessExec, automatic Submit or Advance. There is no old-name
alias or fallback.
