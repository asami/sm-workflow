## Contract and evidence boundary

`SmWorkflowConfiguredComponentFactory` resolves the canonical initialization
parameters before invoking one host-owned bundle binder. Each built component
retains its own creation capsule; a reusable factory cannot select the first
component's Subsystem for later components. `create_Core` does not bind services.
The complete nonempty, unique service bundle is installed together. Declared MCP
operation publication must name actual operations in that bundle.

`ThreeWorkflowLauncherAssembly` composes the native GoalPhase, SplitPhase and
RepositorySync host service assemblies. GoalPhase and RepositorySync consume the
same repository-closure declaration. Complete native validation, review, closure
and independent Human ports are required; missing dependencies are errors, not
legacy entry services or fabricated authority. Parameter data does not create
Human consent, review evidence, process grants, storage providers or a new pool.

The existing GoalPhase configured factory delegates its historical single-service
and additional-binding interface to this bundle factory. Its regressions remain
required; this compatibility adapter is not the default native three-service
installation.

The normal `impl.ComponentFactory` now selects
`ThreeWorkflowHostParameters.factory`. Its required, closed
`sm-workflow.host.definition` carries repository target and validation/review/
closure policies, not executable grants or Human consent. The existing
Subsystem bootstrap owns the common pool and managed process lifecycle.
`NativeHostEvidence` reads separately host-issued records through the incoming
managed DataStoreSpace/clock; the port adapters bind the complete current Start,
Human answer, review result or authorized effect. Missing or crossed evidence
cannot become a success receipt. No public completion Operation issues those
records, and no private fixture enrollment is used by the normal launcher spec.

## Executable scenarios

`SmWorkflowConfiguredComponentFactorySpec` uses canonical public construction to
exercise per-component resolved parameters/owner, one bundle invocation, inherited
job/storage context, no incoming authenticated actor at composition, failure
before binding on invalid parameters, no partial installation on binder failure,
and invalid service/publication refusal. Generated service declarations in these
mechanics scenarios are explicitly wiring probes, not native workflow execution.

`ThreeWorkflowLauncherAssemblySpec` checks the fifteen actual generated provided
operation identities, one trusted host decode after canonical parameter
resolution, and incomplete host refusal without manufactured dependencies. These
are not a positive three-workflow Start/advance/completion proof.
