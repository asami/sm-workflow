# Published dependency source and artifact adoption

This continuation handles an actual successfully published dependency followed
by a retained primary packaging capacity failure in the same native Session.
The dependency may subsequently be repaired and published through another
normal owner. Old success, primary failure, accepted work, Plan/base, completed
Steps and repair accounting remain immutable history.

## R1 — Normal recollection and historical origin

Use existing `describeGoalPhaseDependencySourceRevision` with `--input` or
`--inputResource`. Its proposal Record is a strict closed object:

```text
schemaVersion: sm-workflow.goal-phase-published-dependency-source-proposal.v1
source: ordinary v5 source-only Proposal
publication:
  result: exact normal LocalPublicationResult {status, reason, publication}
  collectOperation: org.simplemodeling.textus.SmWorkflow.LocalPublicationService.collectLocalPublication
  recollectionReference: ContextReference
  publicationOwner: actual selected external owner
  observedAt: ISO instant
  publisherProcessPolicy: fixed canonical process policy
  destination: absolute publication destination URI
  artifact: ContextReference
```

The complete result must be published/ready, have no next preparation and retain
complete untruncated stdout/stderr with an actual Exited(0) at the exact selected
workspace's declared publish-local program. Component, workspace, dependency and
target remain exact. The publisher's participant, request and source remain
literal. Owner, destination, artifact, reference and result are independently
attested as one whole binding; caller JSON and successful output alone provide
no authentication. Existing independent evidence provisioning owns admission.
No new provider or network client is involved.

The runtime constructs `publishedOrigin` from actual native candidate/history,
the successful prefix and failed primary. Original requests are read with their
own identities and checked against the latest results. Unselected dependencies
must still have their old source. The primary source/failure remain unchanged
and no check may have started. A legacy dependency capture may supply its real
historical snapshot without an unavailable historical Guard; no old file hashes
are inferred from current bytes. Old source/UNKNOWN schemas remain unchanged.

## R2 — Exact source selection and ordinary capture

The v9 source target carries exactly one selected dependency, the genuine
predecessor/ancestor chain, inherited acceptance and a declared higher source
binding. Logical Component/repository/workspace/root/branch remain the same.
Old owned paths/checks/acceptance remain covered. Any necessary concrete added
paths are named in the origin and declared binding and explicitly covered by
this new source Human selection. No prior approval is invented. Selected
changes inherit the original base; explicit committed succession uses the
existing typed ancestry/inventory owner.

`AdoptPublishedDependencySourceRevision` and Defer are the available choices.
The existing independent source Human provider binds the entire concrete
target, including the full publication observation. Source adoption saves one
CAS Direction and performs no staging, artifact adoption or publication. Defer
writes nothing. Actual source and recollection/artifact references are required
by passive preparation; observation time cannot be later than evidence time.

Separate ordinary Advance uses the existing typed Git/File/UoW capture engine,
separately tagged published-source causation and v10 capture schema. Its exact
pre-stage Guard equals the original publisher Result source. Actual selected
bytes/modes are covered. Typed staging accounts for the index-only transition
to the real post-stage Guard; the publisher's original source is never rewritten
to pretend that it was already staged. Freshness subsequently uses that real
post-stage Guard. Generation increases once, preserving primary snapshot/diff,
original source history and all repair accounting. Completed capture recollects;
an incomplete intent remains UNKNOWN and is never automatically replayed.

## R3 — Separate artifact adoption

After capture, session-only
`describeGoalPhasePrerequisitePublicationRecovery --sessionId …` returns
`sm-workflow.goal-phase-published-dependency-artifact-adoption.v1`. It binds the
actual current candidate/controller/frontier, capture/source-Direction reference,
historical origin, complete recollection, post-stage Guard and fixed policies.
The existing recover input offers `AdoptRecollectedPublishedDependencyArtifact`
or Defer, with no hostCorrection. Existing prerequisite-publication-recovery
Human evidence binds the whole target and answer. Missing, crossed, stale or
merely claimed evidence refuses.

Recover saves one adjacent mechanical artifact fact only. It neither collects
the external request under consumer identity nor calls dependency ensure/execute,
and it never replaces the old success. Duplicate/stale answers cannot create
another fact. Source/artifact facts remain separate. The existing evidence
provider may admit already applicable genuine concrete authorization; there is
no fixed number of messages and no inheritance from an unknown future target.
Development approval alone grants no actual consumer choice.

## R4 — Existing host recovery and normal checks

After artifact adoption, the same session-only describe returns host-recovery
v2 with explicit `publishedDependencyAdoptions`. It retains the original failed
primary and old successful dependency prefix, together with the new native
source capture and actual external artifact fact. V1 bytes are unchanged.
Original request identities are validated against the historical origin, never
against a fabricated request at the new source revision.

Host correction and one-primary Human authorization retain their existing exact
semantics. Before the primary effect, unchanged dependencies use the original
strict checks. The selected dependency uses its typed adoption, actual capture,
current post-stage freshness and exact attested external result. It is never
republished. The primary source/latest failure remain exact until its single
successor. Ordinary selected checks and ReviewStep use the new dependency
capture. Missing source/artifact/host authority permits no fresh check, commit
or publication. Repeated Advance collects successful effects.

public outputs, normal references and the same isolated Session in the handoff.

is two (original plus intentional external repaired publication), with zero

of this qualification. Authoring this suite does not claim it has passed;
