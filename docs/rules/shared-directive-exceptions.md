# Shared directive exceptions

## Git-managed journal purpose

The user's explicit direction of 2026-11-16 specializes the shared
`document-lifecycle.md` description of a chronological journal for this
repository's `docs/journal` only.

Keep the considerations and reasons behind design/note documents. Consolidate
them by subject, in English, only at the user's request. Do not keep
source-update chronology, command/test/review
reports or duplicate specifications as journal files. Git owns source history;
operation records own execution observations. Necessary ending decisions and
unresolved dispositions remain in Phase/management documents.

This is a documentation-placement rule. It authorizes no change to runtime
Journal/Evidence contracts, retained workflow data, existing authority or Phase
acceptance. A journal explanation is not a new normative product requirement.
