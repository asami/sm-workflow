# Strict Scala 3 collection authoring

Use value membership when asking whether a value is present. Use identity lookup
only when the model declares an identity relation and the caller intends that
relation. A lint finding cannot choose that business meaning for the caller.

The adopted Core source is `e4972601207d4597f0ed3aa77fc0ed62fb286c75`.
Its available import is `org.goldenport.util.TypeSafeCollections.*`:

| Intent | Delivered call | Required evidence |
| --- | --- | --- |
| Value membership in `Vector[A]` | `values.typeSafe.containsEq(query)` | An intentional `Eq[A]`; the query type must equal the captured `A` |
| Mandatory identity | `values.typeSafe.identifiedBy(relation)` | An explicit `Identified[A, I]` and intentional `Eq[I]`, with `I <: UniversalId` |
| Optional identity | `values.typeSafe.identifiableBy(relation)` | An explicit `Identifiable[A, I]` and intentional `Eq[I]`, with `I <: UniversalId` |
| Lookup after selecting a relation | `ids.containsId(id)` / `ids.findById(id)` | The captured identity type `I`; lookup returns the first present matching ID |
| Stable identity distinct | `ids.distinctById` | First identified representative wins; every unidentified occurrence remains |

The source API and its bounded producer checks are accepted; binary availability
must be established separately on the selected consumer classpath. Importing an
extension does not change `Vector.contains`, Set/Map equality or existing method
resolution. A precompiled `contains` can still accept a different element type
under strictEquality. The existing lint diagnostics about incompatible original
types and implicit array equality retain their check-only behavior. They perform
no automatic membership rewrite.

For arrays, supply the intended structural or reference `Eq` explicitly. For
entities, inspect a generated or existing `Eq` before using it for value
membership: an ID-based Eq has identity semantics even when passed to
`containsEq`. Do not infer a new ID relation from arbitrary fields, add broad
`Eq[Any]`/universal `CanEqual`, cast operands or call unchecked equality to silence
a diagnostic. An explicitly declared broad collection remains broad; retain the
domain type where the domain contract requires it.

The delivered operations use linear Eq scans. Lookup/membership are O(n);
identity distinct is O(n²) in the worst case and resolves no payload conflict.
They establish no hash coherence, grouping or sorted-collection contract.

For the strict module's explicit C qualification, prepare the exact adopted Core
binary through the existing publication/resolution owner and retain source,
coordinates, artifact digest and the actual Compile/Test classpaths. The current
ambient `0.4.3-SNAPSHOT` label supplies no such proof. A selected consumer lacking
the API must fail compilation; keep its C acceptance open. Do not substitute a
different comparison or silently disable the selected qualification. Ordinary
builds keep the existing B-stage selection until C qualification is explicitly
requested. See the [consumer preparation record](../notes/phase8.1-producer-deliveries.md#slp-c3-consumer-preparation--2026-11-21).


Actual generated C3 API calls are delivered by Cozy
`dd1b826e6ec55ff07edace688b8e6383a9eb5c40`. The admitted public generation of
`workflow-semantic-outcome.cml` selects them only when the generator JVM receives
`-Dcozy.generation.logical-action-membership=core-c3`. The logical-action compiler
uses String value membership with a private `Eq[String]`, preserving selection
order and existing duplicate policy. Its Strings are not an inferred business
identity relation. Unselected older-Core generation retains its prior output.

For strict consumer qualification, set `qualification.core_generated_source_dir`
or `SM_WORKFLOW_STRICT_CORE_GENERATED_SOURCE_DIR` to the adopted selected-output
resource or an equivalent fresh public generation. The build requires the exact
qualified compiler/ABI hashes and stages unchanged generated files as managed
sources. Missing, duplicate, legacy or changed output is a selection failure;
missing Core APIs are compilation failures. Preserve these diagnostics instead
of substituting handwritten source, editing generated bytes or disabling C.
Machine locations remain local configuration. The producer's observed strict
checks do not supply the consumer's pending strict compile, produced-class
behavior checks or applicable handwritten lint. Managed output remains under
producer qualification, outside the handwritten lint Action.
